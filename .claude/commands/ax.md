인자: $ARGUMENTS (경로들. 비워도 된다)

## 할 일

1. `ax_status` 를 부른다. 장부에 무엇이 들어 있는지 그대로 보여준다.
2. **인자로 경로를 받았을 때만** 그 경로들로 `ax_check` 를 부른다.
3. 결과를 짧게 정리한다. 겹치면 **재시도하지 말고** 누가 왜 잡고 있는지와 함께
   비어 있는 다른 곳을 제안한다. 같은 요청은 몇 번을 보내도 같은 답이 온다.

## 🔴 저장소를 뒤지지 않는다

**인자가 없으면 `ax_status` 만 부르고 끝낸다.** 무엇을 건드릴지 추측하지 않는다.

예전에는 이 명령이 *"이번 대화에서 건드릴 것으로 보이는 경로를 확인해라"* 라고
시켰다. 그러면 에이전트는 추측하려고 저장소를 뒤진다 — 파일 목록, git 상태,
문서 몇 개. **한 줄 확인하자고 대화 하나치 컨텍스트를 쓴다.** 그리고 그렇게
추측한 경로는 대체로 틀린다. 정작 건드릴 파일은 일을 시작해 봐야 정해지기 때문이다.

잡을 곳이 정해졌을 때 부르는 것이 맞다:

```
/ax frontend/src/pages/Trip.tsx
```

정해지지 않았으면 장부만 보면 된다. 그게 이 명령의 기본값이다.
