# 04 — 무엇으로 막나: 지표 두 개를 어제 사건에 대 봤다

원본: `원본/05-지표-실측.md`

---

## 1. 후보 지표 두 개

| | 지표 | 무엇을 보나 | 언제 뜨나 |
|---|---|---|---|
| **가** | **내 바탕이 몇 커밋 뒤처졌나** | **내** 브랜치 | 선점할 때 |
| **나** | **그 파일을 만졌지만 아직 안 합쳐진 브랜치** | **남의** 브랜치 | 선점할 때 |

---

## 2. 🔴 그 순간을 재현해서 실제로 대 봤다

두 사람이 선점한 **바로 그 시각**의 저장소 상태를 되살려 쟀다.

### 지표 가) 뒤처진 커밋 수

| | 미리 (20:13) | 예승 (22:28) |
|---|---|---|
| 뒤처진 커밋 **전체** | **4개** | **32개** |
| 그중 **`frontend/app.json` 을 만진** 커밋 | 🔴 **0개** | ✅ **1개** ← 효준의 것 |
| 이 지표로 막을 수 있었나 | ❌ **못 막는다** | ✅ **막는다** |

### 지표 나) 안 합쳐진 브랜치

| | 미리 (20:13) | 예승 (22:28) |
|---|---|---|
| 효준의 브랜치가 안 합쳐진 상태였나 | ✅ **그렇다** (20:41 에 합쳐짐) | ❌ 아니다. 이미 합쳐졌다 |
| 이 지표로 막을 수 있었나 | ✅ **막는다** | ❌ **못 막는다** |

### 합치면

| 사건 | 지표 가 (내 바탕) | 지표 나 (남의 브랜치) |
|---|---|---|
| **20:15 미리** | ❌ | ✅ |
| **22:31 예승** | ✅ | ❌ |

🔴 **어느 하나만으로는 절반밖에 못 잡는다. 정확히 엇갈린다.**

---

## 3. "뒤처진 커밋 수" 는 그대로 쓰면 안 된다

지표 가) 는 **경로로 자를 때만** 쓸 만하다. 쌩숫자는 거짓말을 한다.

| 상황 | 쌩숫자 | 경로로 자른 숫자 | 진실 |
|---|---|---|---|
| 미리 20:13 | 4 뒤처짐 → *"괜찮네"* | **0** | 🔴 위험이 **밖에** 있었다 |
| 예승 22:28 | 32 뒤처짐 → *"많네"* | **1** | 🔴 그 **1개가 전부**였다 |

**32 라는 숫자는 아무것도 안 알려 준다.** 31개는 내 파일과 상관없는 남의 화면
작업이었다. 쓸모 있는 신호는 **"내가 잡으려는 경로를 건드린 커밋이
내 바탕 뒤로 몇 개 있나"** 하나다.

> 그리고 이 정확한 지표조차 **미리 건은 못 잡는다.** 그때 위험은
> 아직 **어느 브랜치에도 안 합쳐진 채** 떠 있었기 때문이다 (03 번 문서의 "창").

---

## 4. 비싸지 않나 — 쟀다

> 🔴 **2026-09-11 정정.** 처음에 **4,475ms** 라고 적었는데 **틀렸다.**
> 그건 검사가 느린 게 아니라 **내가 브랜치 100개를 하나씩 `git` 을 새로 띄워
> 돌았기 때문**이었다. `git` 한 번으로 같은 답을 내면 **89ms** 다 — **50배**.
> 낡은 실측을 지우지 않고 남긴다. 다음 사람이 "느리니까 범위를 잘라야 한다" 는
> **틀린 결론**을 다시 내지 않게.

두 지표를 각각 **명령 한 번**으로 구현해서 쟀다. (`frontend/app.json` 기준)

| 지표 | 명령 | 시간 | 출력 | 토큰 |
|---|---|---|---|---|
| **①** 내 바탕 뒤로 이 경로를 만진 커밋 수 | `git rev-list --count 바탕..dev -- 경로` | **49 ms** | `3` (숫자 하나) | **~10** |
| **②** 이 경로를 만졌지만 dev 에 없는 브랜치 | `git log --all --not dev --source -- 경로` | **89 ms** | 635 바이트 (4줄) | **~200** |
| | **합계** | **~140 ms** | | **~210** |

**겹치는 게 없으면 ②는 0바이트**다. 대부분이 이 경우라 평상시 비용은 사실상 ① 뿐이다.

| 걱정 | 실측 답 |
|---|---|
| 토큰이 많이 들까 | 🔴 **안 든다.** 최악이 210토큰, 평소엔 10토큰. AI 가 브랜치를 읽는 게 아니라 **git 이 계산하고 결과만 온다** |
| 느려서 사람이 끄지 않을까 | 🔴 **0.14초다.** 선점이 원래 쓰는 시간에 묻힌다 |
| 매번 떠서 시끄럽지 않을까 | **겹칠 때만 뜬다.** 안 겹치면 아무것도 안 나온다 |
| 왕복이 늘지 않을까 | **안 는다.** 이미 선점이 도는 자리에 붙는다 |

**범위를 최근 2주로 자르는 것은 쓸모가 없다** — 원격 브랜치 100개 중 91개가
최근 2주 안에 움직였다. 자를 것은 기간이 아니라 **명령을 띄우는 횟수**였다.

## 5. 정리

```
        ┌─────────────────────────────────────────┐
        │  선점할 때 두 가지를 같이 본다           │
        ├─────────────────────────────────────────┤
        │                                         │
        │  ① 내 바탕 뒤로, 이 경로를 만진 커밋     │  ← 낡은 바탕 (예승 건)
        │     이 몇 개 있나                       │
        │                                         │
        │  ② 이 경로를 만졌지만 파트 dev 에        │  ← 보이지 않는 창 (미리 건)
        │     아직 없는 브랜치가 있나              │
        │                                         │
        └─────────────────────────────────────────┘
                  둘 다 있어야 구멍이 닫힌다
```

**①은 명령 한 줄이라 거의 공짜다. ②는 4.5초라 범위를 잘라야 한다.**

## 6. 🔴 2026-09-11 — 만들었다 (axMap 1.2.2)

위 설계대로 **경고만 하는** 검사 둘을 선점에 붙였다.

| | |
|---|---|
| 판정과 문장 | `src/overlap.mjs` (git 호출 없음 — 순수) |
| git 을 부르는 곳 | `bin/axmap.mjs` 의 `printOverlap` |
| 테스트 | `test/overlap.test.mjs` |
| 판 | `1.2.1` → **`1.2.2`** — 막지 않으므로 patch 다 |

실제 데이터로 확인했다. 예승 님이 22:28 에 선점한 그 순간을 되살려
`frontend/app.json` 을 잡아 보니 **두 항목이 다 떴다** —
[1] 에 미리·예승의 안 합쳐진 커밋 둘, [2] 에 효준의 이미 합쳐진 커밋.
**어제 놓친 것을 지금은 잡는다.**

머지 커밋은 뺐다(`--no-merges`). 처음 재 보니 [2] 의 세 칸 중 하나를
`Merge branch …` 한 줄이 잡아먹고 있었는데, 그 줄은 누가 무엇을 했는지를
알려 주지 않는다.
