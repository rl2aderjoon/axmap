# 기존 앱 대화의 로컬 직접 중계

2026-11-06 · S15P31E109-207 · 구현 및 실사용 검증 중.

기존 Claude 앱 대화와 기존 Codex 앱 대화 사이에 AI가 아닌 로컬 중계 프로세스 하나를 둔다.
별도 모델·대화 생성이나 문맥 이관은 없다. 연결된 앱은 Stop 훅에서 상대를 기다리지 않는다.
기존 `bridge send --from-session` 요청 큐와 요청 ID별 명시적 회신을 사용한다.

```powershell
node bin/axmap.mjs bridge native --codex <Codex의 axMap 세션 UUID> --claude <Claude의 axMap 세션 UUID> --cwd <대상 저장소>
```

Codex 앱이 제공하는 `CODEX_APP_TOOLS_PIPE_PATH`를 상속하는 자식 프로세스로 실행한다.
Windows에서 상주 실행할 때는 `Start-Process -WindowStyle Hidden`을 사용한다.
CLI/npm의 과거 app-server control socket과 현재 앱의 도구 파이프는 서로 다른 경로다.

## 전달과 완료

- Codex: 앱 도구 파이프의 `send_message_to_thread`로 원래 대화 UUID에 전달한다.
- Claude: 세션 레지스트리의 원래 대화 UUID와 Named Pipe를 대조하고, 해당 파이프의
  프로세스 시작 정보와 인증 키를 확인한 뒤 세션 수신 프로토콜로 전달한다.
- 일반 요청은 기존 로컬 큐에 넣고 파일 변경 알림으로 처리한다. 파일 알림 누락 복구와
  중계 프로세스의 생존 확인용 주기는 5초다. 사용자 작업의 실행 시간 한도가 아니다.
- 새로운 요청에 현재 중계 UUID를 기록한다. 연결 전 과거 요청이나 다른 중계의 불명 전송은
  자동으로 재실행하지 않는다. 연결 후 실패는 불명으로 남기고 재전송하지 않는다.
- 파이프 쓰기 성공은 제출이다. 실제 응답은 요청 UUID를 지정한 `ax_reply`가 기록한다.
  수신 정책의 hold/refuse는 바꾸지 않는다. 실제 답이 없으면 완료로 보고하지 않는다.
- 요청·회신만 전달하며 확인 쪽지에 다시 답하는 루프는 만들지 않는다. 왕복·토큰·전체 실행
  시간 제한을 새로 두지 않는다. 공급자의 권한·수신 정책과 자체 제한은 그대로 적용된다.
- 네이티브 전달을 선택한 세션은 긴 Stop 대기를 생략한다. 종료할 때 기존 대화 모드는 끄지 않는다.
  중계가 비정상 종료되면 연결이 끊긴 것으로 처리하고 새 요청은 미전송 큐에 보관한다. 과거의 긴 훅
  대기로 되돌아가지 않으며 사용자 입력과 원래 작업은 계속 받을 수 있다.
- 상대 응답을 기다리는 도구 호출을 앱에서 유지하지 않는다. 작업 중 받은 메시지는 앱의
  작업이 끝날 때까지 axMap 큐에 보관하고 사용자의 새 입력은 그대로 받는다. 사용자 입력으로
  협업 요청을 취소하지 않는다. 일반 마지막 답변을 회신으로 추정하지 않는다.

## 검증 범위

`test/app-native.test.mjs`는 실제 로컬 소켓의 프레임 분할, 연결 전 실패, 기존 대화 UUID 유지,
원래 요청의 완료 회신, 오래된 요청 재전송 방지, 훅 대기 생략과 신원 불일치 거절을 검증한다.

실제 앱 실측은 별도 기록하며 로컬 제출 시간과 모델 응답 포함 시간을 구별한다.

각각 원래 Claude 대화의 실제 응답으로 completed가 되었고, 원래 Codex 대화에 회신이 들어왔다.

두 수치는 다른 측정 구간이며 네트워크/모델 처리 시간의 개별 분해나 일반 성능 보장은 아니다.

현재 연결은 사용자가 지정한 두 기존 대화를 사용한다. 이미 떠 있는 구버전 MCP 서버는 모듈이 캐시되어
있으므로 재연결 전에는 최신 설치본의 `bridge send --from-session ... --cwd ...`를 사용한다.
대기열 접수 성공만으로 실제 도착을 주장하지 말고 요청 UUID의 완료 및 회신을 확인한다.

## Windows 로그인 및 앱 재실행 자동 연결

2026-11-06 후속 사용자 요청에 따라 현재 PC에 자동 연결을 설치했다.
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`의 `AxMapNativeRelay` 값이
`~/.axmap/bridge/native-autostart/robotable-109-start.vbs`를 실행한다. VBS는 콘솔을 숨기고
설치본의 `tools/app-native-supervisor.mjs`를 시작한다. 앱이나 모델은 실행하지 않는다.

- 설정: `~/.axmap/bridge/native-autostart/robotable-109.profile.json`.
  기존 두 대화 UUID와 대상 저장소 S15P31E109, 고정 중계 UUID를 보관한다. 인증 토큰은 넣지 않는다.
- 감독 프로세스는 Windows Named Pipe로 단일 실행을 보장한다. 로그인 실행 파일을 두 번
  실행해도 같은 설정의 중계가 중복 실행되지 않는다.
- 앱이 꺼져 있으면 기다리고, 사용 가능한 Codex 앱 도구 파이프를 다시 찾는다. 예전 파이프가
  사라지면 새 파이프로 교체한다. 후보가 여러 개이고 기존 연결을 확인할 수 없으면 임의로 선택하지 않는다.
- Claude 원래 대화의 실행 중 수신 파이프와 Codex 원래 대화의 존재를 읽기 전용으로 확인한다.
  새 대화를 생성하거나 모델 턴을 시작하는 호출은 복구 과정에 없다.
- 고정된 중계 UUID로 재연결하므로 아직 전송하지 않은 큐와 완료 회신을 이어 처리할 수 있다.
  제출 중이거나 전달 여부가 불명인 요청을 자동 재전송하지 않는다.
- 현재 상태: `~/.axmap/bridge/native-autostart/<설정 UUID>.status.json`.
  `connected`, `waiting-codex`, `waiting-claude` 등 실제 확인 상태를 기록한다.
  상태 변경과 요청 이벤트만 별도 `.events.jsonl`에 남긴다.
- 앱 상태 확인 주기는 3초다. 기존 작업이나 사용자 입력을 붙잡는 훅 대기는 사용하지 않는다.
  재부팅 후 로그인하면 감독 프로세스가 시작되고, 두 앱과 원래 대화의 수신 경로가 사용 가능할 때 재연결한다.
  종료되거나 삭제된 대화를 새 대화로 대체하거나 앱을 강제로 실행하지 않는다.

설치 검증은 격리된 경로에서 시작 파일 생성·인용, 앱 미실행 대기, 파이프 교체, 중복 실행
방지를 검사했다. 실제 PC에서는 로그인 레지스트리 값 재조회와 동일 VBS 실행, 감독 프로세스
재시작 및 Codex 세션 환경 변수 제거 뒤 원래 두 대화의 자동 연결을 확인했다.
실제 PC 재부팅이나 사용 중인 앱의 강제 재시작은 하지 않았다.
관련 단위 검사, 전체 `npm test`, 기본·비교·경합 데모는 모두 통과했다.

## 전달 언어와 중복 표시

사용자 요청에 따라 네이티브 요청·회신은 사용자 언어 하나로 작성한다. 언어는 전달할 때마다
`AXMAP_LANGUAGE`, `~/.axmap/settings.json`의 `language` 또는 `locale`, Claude 사용자 설정의
`language` 순으로 확인한다. 현재 한국어와 영어 표시를 지원하고 미설정 시 이 작업공간의
기본 언어인 한국어를 사용한다. 현재 PC의 Claude 설정은 `korean`이다.

한국어에서는 `[axMap 요청 UUID]`, `[axMap 회신 UUID]`로 표시한다. 요청에는 같은 내용을
영어로 병기하지 말고 한국어로 한 번만 답하도록 안내한다. 회신은 원래 본문을 한 번만 넣고
항상 붙이던 상태·세션·후속 안내 문단은 생략한다. 원문에 번역문이나 요약을 덧붙이는 모델 호출은 없다.
언어가 바뀌거나 구버전 메시지가 남아 있어도 한국어·영어 표식을 모두 읽어 같은 요청 UUID로 대조한다.

Claude·Codex가 수신 메시지에 자체적으로 붙이는 출처·보안 시스템 문구는 공급자 앱의 영역이며
이 변경은 그 문구나 권한 검사를 수정하지 않는다.

공식 수신 경로: https://code.claude.com/docs/en/cross-session-messaging#the-sessions-inbox-socket
Codex 앱 도구 파이프의 프레임과 호출 필드는 설치된 공식 `codex-app-tools/server.mjs`에서 확인했다.
Claude 프레임 필드는 공개 구현 `PeterSR/claude-code-socket-transport`의 프로토콜 설명도 대조했다.

## 요청·회신 보존과 작업 경계 처리 (2026-11-06 후속)

- 요청은 `requests/<UUID>.json`에, 명시적 회신은 같은 레코드의 `result`에 원자적으로 저장한다.
  사용자 입력, 중계 연결 단절, 앱 종료로 취소하거나 만료시키지 않는다. 이미 종료·대체된
  과거 레코드는 임의로 되살리지 않는다.
- 중계는 훅이 확인한 `idle && fullyIdle`이고 승인 대기가 없는 시점에만 요청·회신을 전달한다.
  훅과 같은 수신자 잠금을 사용한다. 앱 자체의 새 사용자 입력이 경합하면 앱의 기본 큐 정책을 따른다.
- 작업 중 다른 사용자 입력이 들어와도 제출된 요청은 남는다. Stop 경계에서 남은 요청을
  안내하며 긴 대기는 하지 않는다. 마지막 일반 답변은 회신으로 수집하지 않는다.
- `ax_reply(id, session, text)` 또는 아래 CLI로 요청별 회신을 저장한다. 같은 본문 재접수는
  멱등이고 완료 본문 변경·다른 수신자·다른 저장소·불명 요청에 대한 완료는 거절한다.

```powershell
# 회신 본문은 stdin으로 넘긴다.
node bin/axmap.mjs bridge reply --request <요청 UUID> --session <내 axMap UUID> --cwd <대상 저장소>
```

- 회신은 상대가 작업 중이면 저장만 하고 idle에서 원래 대화로 전달한다. 자동 ACK는 만들지 않는다.
- 일반 `ax_message`도 연결된 수신자가 idle일 때 편지함 회수 알림을 한 번 보낸다. 메시지는
  `ax_mailbox(take=true, at=checkpoint)`로 회수한다. 알림 전송 불명은 재전송하지 않으며
  원본은 편지함에 남는다. 일반 알림의 기존 TTL·명시적 topic 병합 정책은 그대로다.
- 재연결 뒤 미전송 요청과 미반환 회신을 이어 처리한다. 제출됐지만 미회신인 요청은 ID와
  원문 조회 방법만 안내하여 기존 작업을 중복 실행하지 않게 한다. 보내는 도중 끊긴 불명 전송은
  자동 재실행하지 않는다.
- 설정의 `additionalSessions`에는 사용자가 협업 대상으로 지정한 기존 Claude 토론 세션 UUID를
  추가할 수 있다. 등록된 저장소·공급자·대화 신원을 검증하며 새 대화는 생성하지 않는다.

격리된 실제 로컬 소켓 테스트는 사용자 입력·busy 전달 보류·명시적 회신·편지함 알림·중복 호출·
앱 종료·중계 재시작·미회신 ID 알림을 검사한다. 이 테스트 자체를 실제 공급자 앱 왕복 실측으로
소개하지 않는다. 앱별 실제 검증 결과는 별도로 기록한다.

같은 날 실제 기존 Claude 토론 대화 `e52befbd-057c-4c2f-91d8-77cbf472bd06`가 idle인 상태에서
요청 `193994bf-232c-46b7-a2c9-24f6eaff35ea`를 전송했다. 05:33:22.600Z 접수,
05:33:23.065Z 제출, 05:33:34.990Z 명시적 회신 저장을 확인했다.
실제 결과 본문은 `협업 큐 연결 검사 완료`다. Computer Use와 새 대화 생성은 없었다.
이 검사는 쉬는 Claude 재개와 명시적 회신 저장을 검증하며, 이 요청에는 발신 세션을 지정하지
않았으므로 Codex로의 반환 전달 실측을 의미하지 않는다. 반환 큐의 busy 보류와 idle 전달은
위 격리 소켓 회귀 검사로 확인했다.
