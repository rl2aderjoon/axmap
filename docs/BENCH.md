# 벤치마크 프롬프트 (고정)

경로 표현 세 가지를 비교하기 위한 **표준 과제**다.
기준선과 변형이 **글자 하나까지 같은 프롬프트**를 써야 비교가 성립한다.
바꿔도 되는 것은 아래 `[변형 안내]` 자리 한 줄뿐이다.

> 🔴 예전에는 이 파일이 측정 기준만 담고 **프롬프트 본문은 안 담았다.**
> 회차마다 내가 문구를 다시 지었다는 뜻이고, 그러면 회차 간 차이가 도구
> 때문인지 프롬프트 때문인지 구분되지 않는다. 아래에 본문을 못박는다.

측정하는 것:

| | 뜻 |
|---|---|
| **M3 도달 호출 번호** | 경로 표현이 직접 겨냥하는 지표 |
| 총 호출 수 | 전체 속도 |
| 클릭 빗나감 횟수 | 물리 정지 효과 (기준선부터 0에 가까워야 함) |
| M1·M2·M4·M5·M6 | 회귀 감시 — 한 곳을 고쳐 다른 곳이 느려지면 안 된다 |

**주의** — 회차 간 편차가 크다(18~74 호출). 한 번의 차이로 결론짓지 않는다.
변형이 기준선보다 M3 를 **눈에 띄게** 앞당길 때만 채택한다.

## 프롬프트 본문 (이 아래를 그대로 쓴다)

```text
당신은 오늘 이 회사에 입사한 개발자입니다. 이 코드베이스를 처음 봅니다.

사용할 수 있는 것은 브라우저에 열린 http://127.0.0.1:7902/ 하나뿐입니다.
이 화면이 회사가 준 유일한 온보딩 도구입니다.

[변형 안내]

절대 하지 말 것:
- Bash, Read, Glob, Grep 등으로 대상 저장소의 파일을 직접 읽지 마세요
- git 명령을 쓰지 마세요
- 웹 검색을 하지 마세요
- 어떤 파일도 수정하지 마세요
- 화면에 없는 지식(이 프로젝트에 대해 이미 아는 것)을 쓰지 마세요

오직 화면을 눌러보고 읽어서 알아내세요.

다음 여섯 가지를 알아내고, **각각에 도달했을 때가 몇 번째 도구 호출이었는지**
번호를 함께 적으세요.

  M1. 이 저장소는 무엇을 하는 물건인가 (한 문장 + 그 근거를 본 화면)
  M2. 실행은 어디서 시작하나 (진입점 파일)
  M3. 진입점에서 이 저장소의 핵심 기능까지 어떻게 이어지나 (경로를 순서대로)
  M4. 새 기능을 하나 넣으려면 어디를 고쳐야 하나 (파일 + 왜 거기인지)
  M5. 어디가 위험한가 / 어디를 조심해야 하나 (근거와 함께)
  M6. 작은 수정을 자신 있게 하려면 어디부터 읽어야 하나

모르면 **모른다고 쓰세요.** 추측해서 맞히는 것보다 "도구가 이걸 안 알려줬다"가
훨씬 값진 보고입니다. 틀린 답은 가장 나쁩니다 — 도구가 거짓말을 했다는 뜻이니까요.

마지막에 반드시 함께 보고하세요:
  - 총 도구 호출 수
  - 막힌 지점 전부. 각각 (a) 무엇을 하려 했나 (b) 화면이 무엇을 했나
    (c) 완전히 막혔나 / 돌아갔나 를 적으세요
  - 클릭했는데 엉뚱한 것이 눌리거나 아무 일도 안 일어난 횟수
  - 이 도구에서 가장 쓸모없었던 것 하나
```

### `[변형 안내]` 자리에 들어가는 한 줄

| 회차 | 문구 |
|---|---|
| 기준선 | (빈 줄 — 아무 안내도 주지 않는다) |
| 변형 ① 호출 사슬 | (빈 줄 — ①은 왼쪽 안내록 ③걸음 안에 있어서 따로 안내하지 않는다) |
| 변형 ② 사다리 | (빈 줄 — 사다리가 기본 배치라 따로 안내하지 않는다) |

🔴 세 회차 모두 빈 줄인 것이 의도다. **안내를 주면 그 안내의 효과를 재는 것이지
화면의 효과를 재는 것이 아니다.** 변형은 화면 자체를 바꿔서 비교한다.

## 다시 여는 법

> 🔴 **하네스가 지금 화면을 안 겨눈다.** 아래 절차를 그대로 밟기 전에
> `tools/persona-bench.mjs` 를 먼저 고쳐야 한다. 그것이 이 절 맨 아래에 있다.

```bash
node axmap/tools/pick-repo.mjs --no-serve          # 새 저장소 추첨 (통째 클론)
node axmap/app/server.mjs <받은경로> 7902 --readonly
```

M6·M7(겹침을 사람이 계산할 수 있나)을 재려면 **장부에 claim 이 심겨 있어야 한다.**
대상 저장소에서 `axmap init` 을 먼저 부르고, `git config user.name` 이 비어 있으면
`init` 이 조용히 실패하므로 그것부터 확인한다.

🔴 **평가 클론의 `origin` 을 로컬 베어 저장소로 바꾼다.** 안 그러면 장부가 남의
GitHub 으로 나간다. 남의 저장소를 재면서 그쪽에 우리 브랜치를 밀어넣는 일이 된다.

지시문까지 남아 있는 판은 [`bench-runs/20260820T0630Z-ziti-formats/`](bench-runs/20260820T0630Z-ziti-formats/)
가 가장 완전하다. 세 회차 전부의 원문과 한계는 [`bench-runs/README.md`](bench-runs/README.md).
