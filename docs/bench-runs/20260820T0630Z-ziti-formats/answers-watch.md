조건: 브라우저 하나 (`http://127.0.0.1:7902/?watch=1`). 사전 지식 0.
총 도구 호출 **34회** (답 파일 저장·탭 닫기 포함).

## M1. 이 저장소는 무엇을 하는 물건인가

- **답:** OpenZiti — 네트워크 서비스를 인가받지 않은 사용자에게 아예 보이지 않게 만드는
  오픈소스 제로트러스트 네트워킹 플랫폼(`github.com/openziti/ziti/v2`). 모든 연결이
  암호학적 신원으로 인증되고, 정책으로 인가되며, 종단간 암호화된다.
- **무엇을 보고:** 왼쪽 사이드바 ① 걸음의 카드에 `github.com/openziti/ziti/v2` 와 README
  발췌가 **글자 그대로** 있었다 (출처 표시 `README.md`). 바로 아래 "무엇으로 이뤄져 있나"
  막대: controller 925 · ziti 300 · router 182 · tests 168 · zititest 164.
  → controller 막대가 눈에 띄게 가장 길다(이건 그림이 도움이 된 유일한 지점 중 하나).
- **도달한 도구 호출 번호:** **5**

## M2. 실행은 어디서 시작하나

- **답:** 화면이 두 개의 다른 답을 준다. 그대로 적는다.
  - 안내 흐름 ②가 고른 것: `ziti/db-explorer/cmd/ziti-db-explorer/main.go` (38줄).
    지도에도 `②가 고른 진입점` 이라고 붙어 있다.
  - 그러나 **경로 찾기가 실제로 쓴 출발점은 `ziti/main.go`** 였다 ("출발 ziti/main.go").
  - 내 판단: 진짜 CLI 진입점은 `ziti/main.go`. ②가 고른 db-explorer 는 38줄짜리
    곁가지 도구이고, 거기서 import 로 닿는 파일이 8개뿐이다(화면이 직접 말함).
    ②의 순위가 왜 그렇게 났는지는 화면이 설명하지 않았다.
- **무엇을 보고:** ② 걸음의 "파일 안에 실행 시작점이 있다" 목록 —
  `ziti/db-explorer/cmd/ziti-db-explorer/main.go`(import 5), `ziti/main.go`(import 8),
  `zititest/ziti-traffic-test/main.go`(import 28), `zititest/simple-sim/simple-sim.go`(import 1).
  각 줄에 `func main() (package main) · 관례적인 파일명 · Go 관례: cmd/<이름>/main.go`.
  그리고 나중에 경로 패널 머리글 `ziti/main.go 에서 raft.go 까지 3단계`.
- **도달한 도구 호출 번호:** **8** (②의 목록), **23–24** (ziti/main.go 가 출발점임을 확인)

## M3. 진입점에서 핵심 기능까지 어떻게 이어지나

- **답:** 화면이 실제로 그려준 경로 (전부 import, 3단계):
  `ziti/main.go` → `ziti/cmd/cmd.go` → `ziti/cmd/ops/cluster/recover.go`
  → `controller/raft/raft.go`
  즉 main → CLI 명령 트리(cmd.go) → 하위 명령 패키지 → controller 코어.
  그리고 이 저장소의 **중심은 `controller/env/appenv.go`** 다 — 화면 표현으로
  "중심은 추측이 아니라 관측입니다 — appenv.go 를 부르는 파일이 137개로 가장 많습니다".
- **단, 화면이 스스로 붙인 경고를 같이 적는다:**
  "예제·테스트를 뺀 코드 1631개 중 시작점에서 닿는 것이 **474개(29%)뿐**이다.
  계층을 전부 믿지 말 것 — 정적 파싱이 못 푼 연결(동적 로딩·리플렉션·설정 기반 등록)이
  있거나, 진입점이 더 있다." → 이 경로는 전체의 29%만 설명한다.
- **무엇을 보고:** ③ 걸음의 빨간 경고 상자, "진입점에서 이 저장소의 중심까지" 문단,
  그리고 지도 위 "어디까지" 검색에 `controller/raft/raft.go` 를 넣자 나온 4줄짜리
  경로 목록(출발/import/import/import + 오른쪽에 "main.go 에서 / cmd.go 에서 / recover.go 에서").
- **도달한 도구 호출 번호:** **9** (중심 = appenv.go), **23–24** (구체 경로)

## M4. 새 기능을 하나 넣으려면 어디를 고쳐야 하나

- **답: 못 함 — 화면이 스스로 "말할 수 없다"고 답했다.**
  ⑤ 걸음 원문: "150건을 봤지만 **30% 이상 함께 바뀐 파일이 없습니다** — 추가할 때
  정해진 등록 지점이 없는 구조일 수 있습니다", "controller 에 새로 만들 때 어디를
  고치는지 **아직 말할 수 없습니다**".
  화면이 준 것은 묶음 이름뿐: **controller** (README 이름 `Network state`, 파일 925개,
  "routers, services, and topology 를 추적하고 REST API 와 admin 콘솔을 제공").
  고른 이유도 밝힘 — "README 가 이름을 붙인 묶음 중 파일이 가장 많다".
- 추측해서 파일 하나를 적을 수도 있었지만 근거가 화면에 없으므로 적지 않는다.
- **무엇을 보고:** ⑤ 걸음의 빨간 경고 상자 + `Network state` 카드.
- **도달한 도구 호출 번호:** **12** (화면), **13** (전체 원문 확인)

## M5. 건드리면 파급이 큰 파일 하나

- **답:** `controller/env/appenv.go`. 세 가지 다른 지표에서 동시에 1위/상위다.
  - "가장 많이 연결된 곳"(import 이웃) **176** — 목록 1위.
    2~9위도 전부 `controller/env/` (helpers.go 143, sync.go 142, broker.go 142,
    context.go 142, security_ctx.go 141, trace.go 137, routers.go 137, producers.go 137)
    → `controller/env/` 패키지 전체가 이 저장소의 목이다.
  - "숨은 결합이 많은 곳"(import 없이 함께 바뀌는 이웃) **137**.
  - "가장 자주 바뀌는 곳" 커밋 **160** (상위 1% · 중앙값의 53배).
  - ③ 걸음이 "중심"으로 지목한 파일과 같다 (부르는 파일 137개).
  - (go.mod 가 커밋 1891 로 더 자주 바뀌지만 그건 코드가 아니라 의존성 파일이다.)
- **무엇을 보고:** ④ 걸음의 세 목록("가장 자주 바뀌는 곳" / "가장 많이 연결된 곳" /
  "숨은 결합이 많은 곳")과 ③ 걸음의 중심 문장.
- **도달한 도구 호출 번호:** **13** (세 목록 원문), 근거 보강 **9**, **11**

## M6. 지금 다른 사람이 잡고 있는 곳이 있나 — 누가 무엇을

- **답: 있다. 3건이 잡혀 있고, 그 위에 선언 없이 고쳐지는 파일이 1개 더 있다.**

  | 누가 | 작업 | 의도 | 잡은 경로 | 상태 |
  |---|---|---|---|---|
  | `agent-raft` | T-401 | raft 리더 선출 타임아웃 조정 | `controller/raft` (폴더) | 선점만 |
  | `agent-edge` | T-402 | edge 리스너 재연결 처리 | `router/xgress_edge` (폴더) | 선점만 |
  | `agent-cfg` | T-403 | 설정 스키마에 필드 추가 | `controller/config/config.go` | 선점만 |

  - TTL 은 셋 다 약 **215~225분 남음** (내가 보는 동안 실시간으로 줄었다).
  - 상단 집계: **3주체 · 선점만 36 · 작업 중 0 · 선언 밖 수정 1** (단위: 파일 수).
    잡은 건 3건인데 파일이 36개인 이유도 화면이 설명한다 —
    "폴더를 잡으면 그 아래 파일까지 물립니다".
  - **작업 중 0** — 셋 다 잡아만 뒀고 아직 실제로 파일을 고치지는 않았다.
  - **선언 밖 수정 1건: `.gitignore`** (52줄 · 38개 커밋에서 수정됨).
    화면 문구: "선언 없이 수정됨 · **이 파일을 잡은 사람이 없습니다. 고치기 전에 선점하세요.**"
    즉 누군가 claim 없이 고치고 있는 파일이다.
  - 이 장부는 로컬이 아니다 — "N초 전에 **원격 장부**를 확인했습니다 — 다른 컴퓨터에서
    잡은 것도 여기 보입니다" 가 계속 갱신됐다.
- **무엇을 보고:** 화면 맨 위 감시 띠의 "지금 3건이 잡혀 있습니다" 목록(에이전트명·작업ID·
  TTL·의도 한 줄·경로가 **전부 글자로** 적혀 있다), 상단 오른쪽 집계 숫자,
  그리고 `.gitignore` 를 선택했을 때 왼쪽에 뜬 "선언 없이 수정됨" 상태 문구.
- **도달한 도구 호출 번호:** **5** (3건 즉시 보임), **13** (집계·전체 원문),
  **30 · 32** (`.gitignore` 특정)

## M7. 내가 지금 `controller/raft/raft.go` 를 고치면 누구와 부딪히나

- **답: 세 명 전부와 부딪힌다. 한 명은 정면으로, 두 명은 "숨은 결합"으로.**

  1. **정면 충돌 — `agent-raft` (T-401, "raft 리더 선출 타임아웃 조정").**
     `controller/raft/raft.go` 를 선택하니 왼쪽에 바로 떴다:
     **"선점만 (아직 안 건드림)"** / `agent-raft · T-401` / "다른 팀원이 잡음" /
     **"controller/raft 를 잡아서 여기까지 물들었습니다."**
     → 그가 잡은 것은 파일이 아니라 폴더인데, 그 폴더 claim 이 이 파일까지 덮는다.
     아직 안 고쳤을 뿐 소유는 그의 것이다. 내가 지금 손대면 정면이다.
     (참고: 이 파일은 1229줄 · 80개 커밋 · 부르는 것 36개.)

  2. **경로는 안 겹치는데 같은 기능일 수 있는 쌍 — 화면이 2건을 따로 경고했다.**
     - `agent-edge` (T-402) 와: `controller/raft/raft.go` ↔ `router/xgress_edge/hosted.go`
       · n=5 · **lift 8.1** · 공변경 1건
       · 의도: "edge 리스너 재연결 처리 / raft 리더 선출 타임아웃 조정"
     - `agent-cfg` (T-403) 과: `controller/config/config.go` ↔ `controller/raft/raft.go`
       · n=10 · **lift 7.4** · 공변경 1건
       · 의도: "설정 스키마에 필드 추가 / raft 리더 선출 타임아웃 조정"
     이 두 쌍은 **import 로 안 이어져 있다.** 코드를 읽어서는 절대 안 보이고,
     과거에 반복해서 같은 커밋에서 함께 바뀌었다는 히스토리로만 드러난다.
     lift 8.1 = 우연히 같이 바뀔 확률의 8배.
  3. 화면이 붙인 단서: **"거부가 아닙니다. 두 사람이 서로의 의도를 아는 것으로
     충분할 수 있습니다."** → 막는 게 아니라 대화하라는 뜻으로 읽었다.

  **결론:** 손대기 전에 agent-raft 와 먼저 이야기해야 하고(그의 claim 안이다),
  agent-edge · agent-cfg 에게는 "raft.go 를 건드린다"고 알려야 한다.
- **무엇을 보고:** ① `sel=controller/raft/raft.go` 로 파일을 골랐을 때 왼쪽 패널의
  "선점만 (아직 안 건드림)" 카드 — 에이전트명·작업ID·의도·"물들었습니다" 문장이 전부 글자.
  ② 감시 띠 안의 "⚠ 경로는 안 겹치는데 같은 기능일 수 있는 쌍 2건" 블록 —
  두 에이전트 이름, 파일 쌍, n, lift 가 전부 글자.
- **도달한 도구 호출 번호:** **13** (쌍 경고 2건), **18** (raft.go 직접 선택 → agent-raft)

## 5. 🔴 그림만으로 알아낸 것 / 글자만 있었어도 답이 같았을 질문 수

### 글 없이 그림(점·선·크기·색·위치)만으로 알아낸 것

솔직히 **거의 없다.** 네 가지뿐이고, 넷 다 "답"이 아니라 "확인"이었다.

1. **"무엇으로 이뤄져 있나" 막대 길이** — controller 막대가 나머지를 압도한다.
   숫자(925)를 읽기 전에 "이 저장소는 controller 덩어리구나"를 먼저 알았다.
   → 이건 그림이 진짜로 먼저 말해준 유일한 사례다. (그래도 옆에 숫자가 같이 있었다.)
2. **0겹 / 1겹 카드의 세로 위치** — 어느 파일이 어느 파일에 불리는지가 위아래 단으로
   보였다. 다만 각 카드 안에 "main.go 이 부름" 이라고 **글자로도** 적혀 있었다.
3. **claim 3행의 왼쪽 색 띠** — 세 건이 서로 다른 주체임을 색으로 묶어줬다.
   (누가 누군지는 결국 `agent-raft` 라는 글자를 읽어야 알았다.)
4. **선택 피드백** — 고른 claim 칩의 흰 테두리, 활성화된 "선언 밖 수정" 칩의 주황 테두리.
   내 클릭이 먹혔다는 것만 알려줬다. 저장소에 대해서는 아무것도 안 알려줬다.

# **7개 전부 (M1 ~ M7).**

하나도 빠짐없이, 내가 쓴 모든 답의 출처는 **문자열**이다.
M1=README 발췌 카드, M2=순위 목록, M3=4줄 경로 목록, M4=경고 문장,
M5=세 개의 순위 목록, M6=감시 띠의 3행 목록, M7=사이드바 상태 카드와 ⚠ 쌍 경고 블록.
점 하나, 선 하나, 색 하나가 **결정적이었던 답은 0개다.**

### 이 조건이 특히 물은 M6·M7 에서 그림이 실제로 무엇을 해줬나 — **아무것도 못 해줬다**

- **M6** 은 감시 띠의 **글자 목록** 하나로 끝났다. 호출 5, 첫 스크린샷에서 이미
  "지금 3건이 잡혀 있습니다" 아래 세 행에 에이전트명·작업ID·TTL·의도·경로가 전부
  적혀 있었다. 지도는 그때도 노드 1개였고 M6 에 1g 도 기여하지 않았다.
- **M7** 도 전부 글자였다. 정면 충돌은 왼쪽 패널의
  "선점만 (아직 안 건드림) / agent-raft · T-401 / controller/raft 를 잡아서 여기까지
  물들었습니다" 라는 **문장**이 알려줬다. 숨은 충돌 2건은 "⚠ 경로는 안 겹치는데 같은
  기능일 수 있는 쌍 2건" 블록의 **파일 쌍·n·lift 숫자**가 알려줬다.
- 화면은 그림 문법을 아주 친절하게 **글로 설명해놨다** —
  "모양 = 고치는 중 / 잡아만 둠", "색 = 누가 잡았나 / 다른 팀원이 잡음 /
  선언 없이 고쳐짐", "바깥 흰 링 = 지금 고른 것".
  나는 이 범례를 완벽히 이해했지만 **그 문법이 적용된 노드를 단 하나도 못 봤다.**
  겹침(내 것과 남의 것이 어디서 만나는지)은 결국 `raft.go ↔ hosted.go · lift 8.1`
  이라는 **글자**로 읽었지, 두 링이 포개진 그림으로 본 게 아니다.

  "겹쳐 본다"는 이름값은 나에게는 실현되지 않았다.

  충돌**을 잡아낸 것은 소스를 아무리 읽어도 못 얻었을 정보다.
