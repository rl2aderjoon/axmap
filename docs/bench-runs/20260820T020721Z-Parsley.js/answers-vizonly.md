# 신입 개발자 관찰 기록 — 그림만 보고 (설명 패널 없이)

전제: `g1-graphonly-layers.png`, `g2-graphonly-feature.png`, `g3-graphonly-watch.png` 세 장만 봤다.
각 이미지는 처음에 딱 1회씩 Read 로 열었고(총 3회), 이후 질문들은 그 3장의 기억만으로 답했다.
추가로 이미지를 다시 연 적은 없다.

## M1. 이 저장소는 무엇을 하는 물건인가

**답**: `blastmap` 이라는 도구로 보인다. 어떤 코드베이스(대상 저장소)를 파일/기능 단위 그래프로 시각화하고, 여러 사람(에이전트)이 동시에 코드를 고칠 때 "claim(선점)"으로 서로 충돌하지 않게 감시해주는 협업·분석 도구인 것 같다.

**근거**: 세 그림 모두 좌상단에 "blastmap" 로고 텍스트가 있고, g3 의 감시 탭 설명 문단("선점 = claim 했지만…", "고치기 전에 claim 하는 것이 이 프로토콜의 전부입니다")과 g1/g3 하단의 "import 있고 함께 바뀜", "숨은 결합" 같은 통계 상자 문구로 유추했다. 점·선 모양만으로는 이 도구의 목적을 알 수 없었고, 전적으로 글자를 읽어서 안 것이다.

**이미지**: g1, g2, g3
- 도구 호출 수: 3

## M2. 실행은 어디서 시작하나 — 파일 하나

**답**: 못 함.

**근거**: g1 범례에 "○ 시작점 / 흐린 점 = 시작점에서 import 로 안 닿음" 이라는 개념이 있어서 그래프 탐색의 기준점이 되는 노드가 있다는 것은 알 수 있었다. 하지만 이것은 프로그램이 실제로 실행되기 시작하는 파일(엔트리 포인트)이라기보다 "지금 화면에서 무엇을 기준으로 그래프를 펼쳤는가"에 가까워 보였고, 세 그림 어디에도 특정 노드가 "시작점"이라는 표시(빈 원 테두리)를 뚜렷이 달고 파일명을 보여주는 장면을 확인하지 못했다.

**이미지**: g1
- 도구 호출 수: 1

## M3. 이 저장소의 큰 덩어리 셋을 이름으로

**답**: 부분적으로만 가능 — `bower_components`, `src` 는 이름을 확인했다. 세 번째는 못 함.

**근거**: g2(기능 그림)에 이름표 붙은 원 두 개가 보인다: `bower_components`(화면 왼쪽, 다른 점과 이어진 선이 전혀 없이 혼자 떨어져 있음)와 `src`(화면 오른쪽, 위쪽의 작은 무명 회색 점과 실선 하나로 이어져 있음). 상단 글자에는 "기능 3"이라고 적혀 있고 화면에도 점이 3개(두 원 + 위쪽 작은 점) 보여서 개수는 맞아떨어지지만, 그 세 번째 작은 점에는 이름표가 붙어 있지 않아 무엇인지 알 수 없었다.

**이미지**: g2
- 도구 호출 수: 1

## M4. "폼 검증" 관련 기능을 고치려면 어느 파일을 열어야 하나

## 마무리 정리

### 1. 이미지 읽은 횟수 합계 · "못 함" 목록

- 실제 Read 도구 호출: **3회** (g1×1, g2×1, g3×1). 이후 모든 질문은 이 3장의 기억만으로 답했고 추가로 다시 열지 않았다.
- 완전히 "못 함": **M2** (실행 시작 파일)
- 부분적으로 "못 함": **M3** (세 번째 덩어리의 이름), **M6/M7** ("선언 밖 수정" 1건의 실제 파일명)

### 2. 점의 위치·크기·색·연결선 자체가 알려준 것 (글자 제외)

- g1: 가운데 큰 주황 점 하나가 다른 작은 점들보다 확연히 커서, "이게 이 화면에서 제일 중요한 자리"라고 짐작했다.
- g1: 그 큰 점 아래로 선 세 개가 작은 점들을 삼각형 모양으로 묶고 있어서, 이 점들끼리 서로 강하게 얽혀 있는 뭉치라고 봤다.
- g2: `bower_components` 점은 화면 어디와도 선으로 이어져 있지 않고 혼자 떨어져 있어서, 나머지 덩어리와 무관한 고립된 영역이라고 봤다.
- g2: `src` 점은 위쪽의 작은 무명 점 하나와 실선으로 이어져 있어서, 이 둘은 서로 관계가 있다고 봤다.
- g3: `expect.js/` 와 `tooltip.js` 두 점만 유독 굵은 흰 테두리를 두르고 있어서, 이 둘이 현재 화면에서 특별히 선택/주목된 대상이라고 봤다(테두리 자체는 모양이지 글자가 아니었다).
- g3: 대부분의 작은 점이 흐리고 비슷한 색인데, 유독 색이 다른 작은 점(분홍/자주색 계열) 하나가 눈에 띄어서 그 점만 다른 상태에 있다고 짐작했다.

### 3. 글자를 읽어서 안 것

- "blastmap"이라는 도구 이름(세 그림 공통).
- 대상 저장소 경로가 `...Temp\blastmap-eval\Parsley.js` 라는 것(g2 상단).
- 하단 통계 상자의 숫자(0/0/0/160)와 각각의 뜻("import 있고 함께 바뀜", "숨은 결합" 등).
- g3 감시 패널의 사람 이름(jihun, minseo), 작업 ID(PARSLEY-214/231), 잡은 파일 경로, 남은 시간, 작업 설명 문장 전부.
- g1의 "히스토리 부족 — 커밋이 0개뿐이라 공변경으로 판정할 쌍이 없다"는 경고 문장.
- 상단 탭 이름들(파일/기능/PR/사다리/그래프/감시)과 지금 선택된 탭이 무엇인지.

### 4. 그림이 없고 글자(표)만 있었어도 똑같이 답할 수 있었을 질문 수

**4개**: M1, M4, M6, M7. 이 넷은 실제로는 상단 텍스트 패널을 그대로 읽어서 답한 것이라, 같은 정보가 표 형태로만 주어졌어도 동일하게 답할 수 있었다. 반면 M5는 점 크기·연결선이라는 시각 정보가 실질적 근거였고, M3도 점의 고립 여부(배치)가 일부 근거였다. M2는 그림이 있어도 결국 못 찾았다.

### 5. 그림이 오히려 헷갈리게 한 것

- g3 화면 안에 "감시" 전용 색 범례(고치는 중/다른 팀원이 잡음/선언 없이 고쳐짐 등)와, 그 아래 "import 그래프" 전용 점 범례(숨은 결합 있음/없음/시작점)가 동시에 있었는데, 그래프에 찍힌 초록·분홍 작은 점들이 정확히 어느 범례를 따르는 색인지 구분이 안 됐다.
- `expect.js/` 처럼 슬래시가 붙은 큰 원이 실제로는 폴더인지, 혹은 테스트용 외부 라이브러리(assertion 라이브러리로 흔히 쓰이는 이름)인지 판단이 안 서서, "가장 커 보이는 점 = 가장 중요한 편집 대상"이라는 내 판단이 틀릴 수도 있다는 의심이 들었다.

### 6. 무엇을 보고 싶었는데 그림에 없었나

- g3 그래프의 각 작은 점에 파일명 라벨이 없어서, jihun/minseo가 잡은 `parsley/field.js`, `parsley/form.js`, `parsley/ui.js` 가 그래프 상 정확히 어느 점인지 대응시킬 수 없었다.
- "선언 밖 수정" 1건의 실제 파일명이 어디에도 안 보였다(색으로만 암시되는 듯했다).
- 실행 진입점(엔트리 파일)을 명시적으로 짚어주는 표시가 없었다.
- M3의 세 번째 기능 덩어리 이름표.
