# 조사 · Orca(ADE) 에서 axMap 이 가져올 UX 는 무엇인가

2026-08-26 조사. **읽기 전용 조사이고 화면 코드는 한 줄도 고치지 않았다.**

방법: `https://www.onorca.dev/` 를 크롬으로 직접 열어 히어로 탭 다섯 개와
기능 섹션 탭 여덟 개를 눌러 가며 화면을 떴고, DOM 에서 문안과 `poster` 파일명을
그대로 뽑았다. 우리 쪽은 `app/web/shell.{html,css,js}` · `app/web/stage.js` ·
`app/web/words.js` · `app/server.mjs` 를 읽고 `grep` 으로 대조했다.
**기억으로 쓴 문장은 없다.**

🔴 **못 본 것을 먼저 적는다.** 앱을 설치하지 않았다. 그러므로 아래는 전부
**홈페이지가 보여주기로 고른 화면**이고, 실제 사용 중의 밀도·지연·실패 화면은
모른다. 홈페이지 데모는 제품의 가장 좋은 순간만 담는다는 점을 감안해서 읽는다.
색도 `body` 배경 하나만 계산값으로 확인했고 나머지는 픽셀 샘플링을 하지 않았다
([docs/RESEARCH-FLOWCANVAS.md](../RESEARCH-FLOWCANVAS.md) 는 했다 —
그쪽 수치와 같은 급으로 신뢰하지 않는다).

## 0. 한 줄 결론 — 먼저 읽는다

> **Orca 는 터미널을 시각화하지 않았다. 터미널은 날것 그대로 두고,
> 터미널이 만들어 낸 *상태*만 밖으로 꺼내 왼쪽 레일에 올렸다.
> 그리고 그 상태를 바꾸는 유일한 통로가 CLI 다 —
> 에이전트가 `orca orchestration task-create` 를 치면 화면이 스스로 갈라진다.**

그래서 이 문서의 권고는 "Orca 처럼 예쁜 터미널을 그리자" 가 **아니다.**
axMap 은 저 *상태 스트림*을 **이미 갖고 있다** — 그것이 `claim` 이다.
없는 것은 데이터가 아니라 그것을 소비하는 화면이다 (4장).

## 1. Orca 가 자신을 뭐라고 부르는가

홈페이지 문안 그대로:

- 제목: `Ship 100x With The Agent IDE`
- `IDEs were built for you. An ADE is built for you and your agents — worktrees, terminals, browser, and CLI in one app.`

**ADE = Agent Development Environment.** IDE 는 사람만 쓰는 전제이고,
ADE 는 사람과 에이전트가 **같은 창을 공유**하는 전제라는 주장이다.

🔴 이 주장은 우리 제품 명제와 **방향은 같고 대상은 반대**다.
Orca 의 "당신" 은 워크트리·scrollback·SSH·WebGL 을 아는 사람이다
(`no stashing, no branch juggling` · `WebGL rendering, infinite splits`).
axMap 의 "당신" 은 변호사·의사여도 되어야 한다.
**그래서 Orca 의 어휘는 통째로 못 가져온다** — 5장이 그 목록이다.

## 2. 화면 해부 — 네 구역

| 구역 | Orca | axMap 현재 (`app/web/shell.html`) |
|---|---|---|
| 왼쪽 레일 | `Tasks` · `Automations` · `Search` → `Projects` → **워크트리 → 에이전트** 3단 트리 | `#side` — 탭 + **대화 목록** |
| 가운데 | 에이전트 대화 + 터미널, 무한 분할 | `#center > #stage` — ladder 번호 카드 (지도) |
| 오른쪽 | 파일트리 ↔ Source Control ↔ 검색 (아이콘으로 전환) | `#chat` — 스레드 + 입력창 |
| 바닥 상태줄 | 사용량·디스크·연결 상태 상시 표시 | **없다** |

🔴 **가운데와 오른쪽이 정확히 반대다.** Orca 는 대화가 가운데, 파일이 오른쪽.
axMap 은 지도가 가운데, 대화가 오른쪽.

**이 배치는 바꾸지 않는다.** D14 4단계와 제품 명제상 주인공은 지도여야 하고,
`app/web/stage.js` 머리말이 가운데 칸을 지도로 정한 이유("왼쪽 패널이 글자로
쏟아내던 것을 가운데 큰 자리로 옮긴다")가 그대로 유효하다.
Orca 가 대화를 가운데 둔 것은 **대화가 곧 산출물인 제품**이기 때문이다.
우리는 산출물이 지도다.

## 3. 실제로 본 것 — 화면별 기록

### 3.1 히어로 · `Run a fleet of agents`

왼쪽 레일에서 워크트리를 펼치면 `5 agents` 아래로 다섯 줄이 각각
**상태 점 + 문장 + 경과 시간**으로 선다.

```
● checkout-flow-v2                    primary
  feature/checkout-flow-v2
  5 agents ⌄
    ↻ ✳  running checkout regres…       49m
    ○ ⚙  validating EU promo codes       3h
    ○ ⚙  updating checkout e2e tes…      4h
    ○ ⚙  reviewing tax calculation …     4h
    ○ ✳  revert cart rounding to pr…     4h
```

🔴 **에이전트의 이름이 사람이 시킨 문장 그대로다.** 세션 ID 도 `agent-3` 도 아니다.

가운데 대화 칸은 Claude Code 의 출력을 **의미 덩어리로 접어서** 그린다 —
`Ran 1 shell command` · `Read(src/checkout/validators.ts) └ Read 180 lines (ctrl+o to expand)` ·
`Update(src/checkout/validators.ts) └ Added 8 lines, removed 3 lines` + 인라인 diff.
날것의 스크롤이 아니라 **접힌 목록**이다.

바닥 상태줄:
`⚹ ▁▁ 58% 5h · 41% wk   ⚙ ▁▁ 52% 5h · 37% wk   1.2 GB · 4   ⚡2   SSH Connected ●`

### 3.2 `Automate everything` — 이 조사에서 가장 중요한 화면

사람이 한 줄 치고, 에이전트가 **IDE 를 CLI 로 조종**하고, **화면이 물리적으로 갈라진다.**

```
사람:  > fix EU promo code checkout and fan out subtasks

에이전트: I'll decompose this issue into parallel subtasks and dispatch workers
         through Orca orchestration.
  Running 1 shell command…
  $ orca orchestration task-create --spec "Patch regional tax rules in checkout" --json
  → {"id":"task_7f2a","status":"ready"}
  → {"id":"task_9c14","status":"pending"}
  → {"terminal":"term_codex_2","status":"dispatched"}
  → {"pane":"term_codex_2","direction":"horizontal"}
  $ orca terminal split --terminal coord --direction horizontal --command claude --json

  ↓ 그 순간 Terminal 2 · Terminal 3 이 화면에 생겨난다
```

🔴 **터미널 출력은 끝까지 날것의 모노스페이스 텍스트다.**
시각화된 것은 터미널이 아니라 **터미널이 만든 상태**(작업 목록·창 배치)다.

기능 카드도 같은 말을 한다 —
`Orca CLI: Agents drive Orca too: orca worktree create, snapshot, click, fill.`

### 3.3 `Orchestration` — 부모/자식 작업 카드

이 섹션은 비디오가 아니라 **DOM 애니메이션**이라 상태 전이를 그대로 읽을 수 있었다.

```
① ● redesign auth flow
   ↻ ✳  Splitting auth rewrite into 2 PRs…
   [⑂ 2 children ⌄]
   ↻ CREATING WORKSPACES…

② ● redesign auth flow
   ↻ ✳  PR 2/2 ready
   [⑂ 2 children ⌄]
     ● PR 1/2: migrate users.sql
       ✓ ⚙  Adding the email_verified column…
     ● PR 2/2: withSession middleware
       ✓ ✳  Wiring withSession middleware…
```

관찰 세 가지.

- **카드는 두 줄뿐이다.** 1줄 = 무슨 일인가, 2줄 = **지금 이 순간 무엇을 하는 중인가.**
  진행률 막대도 로그 꼬리도 없다. `stage.js` 가 Zapier 에서 가져온
  "번호 + 제목 두 줄" 규율과 **같은 조판**이다.
- **2줄은 현재진행형 평문 문장이다.** `Adding the email_verified column…`
  터미널 마지막 줄을 그대로 보여주는 것이 아니라 **한 문장으로 요약한 것**이다.
- **부모-자식을 선으로 잇지 않는다.** `⑂ 2 children ⌄` 칩 하나와
  오른쪽의 흐릿한 점선 중괄호가 전부다.

### 3.4 `Review AI output` — 검수 대상이 diff 가 아니다

눌렀더니 나온 것은 diff 가 아니라 **`localhost:3000/checkout` 이 실제로 렌더된
브라우저 탭**과 그 옆의 `eu-promo-fix.md` 였다.

`Design Mode` 카드가 한 발 더 간다:
`A real Chromium window per worktree. Click any UI element to send its HTML, CSS, and a cropped screenshot into your agent.`

### 3.5 `Git integration`

오른쪽이 Source Control 로 바뀌고 **커밋 메시지가 이미 적혀 있다**
(`Fix EU promo checkout tax ordering`). `Stage All` · `Create PR` ·
`STAGED CHANGES 2`. 가운데는 `promo.ts — diff` 탭.

### 3.6 기능 카드 문안 (DOM 에서 그대로)

| 카드 | 문안 |
|---|---|
| Parallel Worktrees | `Every task runs in its own isolated git worktree — no stashing, no branch juggling. Fan one prompt across 5 agents, compare, merge the winner.` |
| Design Mode | `A real Chromium window per worktree. Click any UI element to send its HTML, CSS, and a cropped screenshot into your agent.` |
| Annotate AI Diffs | `Drop markdown comments on any diff line, batch them, ship them back to the agent.` |
| Orca CLI | `Agents drive Orca too: orca worktree create, snapshot, click, fill.` |
| Account Switcher & Usage Tracking | `See Claude and Codex usage, rate-limit resets, and hot-swap Codex accounts without re-logging in.` |
| Split Anything | `Arrange agents, terminals, browsers, diffs, and files into split panes that match the shape of the task.` |

## 4. 🔴 우리에게만 있는 것 — 데이터는 이미 있고 화면이 없다

Orca 가 제품으로 내세우는 "누가 어디서 무엇을 하는 중인가" 를,
axMap 은 **프로토콜로 이미 갖고 있다.**

| Orca | axMap |
|---|---|
| `orca orchestration task-create --json` | `axmap claim <경로> --task <ID> --intent "<한 줄 설명>"` |
| 화면이 갈라진다 | 지도에서 그 파일들이 점유 표시로 물든다 — **아직 없음** |
| `orca worktree create` · `snapshot` · `click` · `fill` | `bin/axmap.mjs` + `mcp/server.mjs` — **이미 있음** |
| 에이전트 이름 = 사람이 시킨 문장 | `--intent` 가 정확히 그 문장 — **이미 있음** |

그리고 **서버는 이미 내주고 있다.**

- `app/server.mjs` 의 `liveState()` 가 `readClaims(...)` → `overlay(...)` →
  `liveSummary(...)` 를 만들어 `claims` 와 `summary` 를 반환한다.
- `/api/live` 라우트가 그것을 그대로 내보낸다.
- 🔴 **그런데 `app/web/*.js` 어디에서도 `/api/live` 를 부르지 않는다.**
  소비자는 옛 화면(`overlay.js`)이었고 `141e684` 에서 지워졌다.

> 즉 axMap 은 **Orca 가 제품으로 내세우는 기능의 데이터 계층을 이미 서버에 갖고
> 있으면서 화면만 없는 상태**다. 이것이 이 조사에서 가장 값싼 발견이다.

⚠️ **줄 번호를 여기 적지 않는다.** `grep -n "api/live\|liveState" app/server.mjs`
로 찾는다 — 적어 두면 그 줄이 먼저 낡는다.

### 4.1 먼저 정리해야 할 어휘 충돌

`app/web/shell.js` 의 `S.agent` / `S.agentName` 은 **"어느 AI CLI 를 쓰나"**
(claude · agy · codex)를 뜻한다. Orca 가 말하는 agent(= 지금 뭔가 하고 있는 작업
하나)와 **같은 단어가 다른 뜻**이다.

레일에 claim 을 올리기 전에 이 충돌을 정리하지 않으면 `app/web/words.js` 에
뜻이 두 개인 낱말이 생긴다 — `docs/WORDS.md` 원칙 C 가 막으려던 상황 그대로다.

### 4.2 우리가 유리한 점과 불리한 점

🟢 **유리 —** Orca 의 상태는 자기 앱 안에서만 산다(로컬 프로세스 목록).
axMap 의 claim 은 git 브랜치 `axmap/claims` 에 있어서 **다른 사람 노트북에서
일어난 일도 같은 화면에 뜬다.** Orca 가 팀 단위 병렬을 보여주려면 서버를 세워야
하고, 우리는 `git fetch` 면 된다 — `app/server.mjs` 가 이미 장부를 당겨온다.

🔴 **불리 —** Orca 의 상태는 실시간이고 claim 은 **30분 TTL 의 거친 입자**다.
`--intent` 는 claim 시점에 한 번 고정되므로 "지금 뭐 하는 중"(3.3 의 2줄)을
claim 만으로는 못 그린다. **claim 을 갱신형으로 만들지, `app/lib/session.mjs`
에서 따로 끌어올지 — 이것이 아직 정하지 못한 설계 판단이다.**

## 5. 훔치지 않을 것 — 네 개와 그 이유

| | 왜 |
|---|---|
| **다크 테마** | Orca 는 `body` 배경이 순검정(`rgb(0,0,0)`)이고 서체는 `DM Sans` 다(계산값으로 확인). `app/web/shell.css` 는 Claude 브랜드 크림(`--bg: #faf9f5`)이고 그 선택에 **한글 가독성이라는 근거가 파일에 적혀 있다.** 근거 있는 결정을 인상으로 뒤집지 않는다 |
| **무한 분할 (`Split Anything`)** | "칸이 하나 늘면 파일도 하나 는다"(`shell.js` 머리말). 옛 화면이 3,527줄까지 자란 경로가 정확히 이것이다. **M3 를 앞당기지 않으면 올리지 않는다** |
| **워크트리·scrollback·SSH 어휘** | Orca 는 대놓고 전공자용이다. 이 어휘를 통째로 들이면 `docs/WORDS.md` 원칙 A 를 한 번에 어긴다 |
| **WebGL 터미널 렌더러** | 의존성 0 규칙 위반이고, 우리는 터미널을 **그리는 것이 목표가 아니다**(0장) |

번호는 [IDEAS.md](IDEAS.md) 의 항목과 같은 것을 가리킨다.

| | 항목 | 비용 | 근거 |
|---|---|---|---|
| U1 | 왼쪽 레일에 claim 을 `intent` 문장으로 띄운다 | **낮음** — `/api/live` 이미 있음 | 4장 |
| U2 | 진행 중인 일을 한 줄 현재진행형 문장으로 | 중간 — 4.2 의 설계 판단이 선행 | 3.3 · 안전 지표 |
| U3 | 부모-자식을 선 대신 `⌄ 자식 2개` 칩으로 | 낮음 | 3.3 · `stage.js` 와 같은 규율 |

| U5 | 검수 대상을 diff 가 아니라 돌아가는 앱으로 | **높음** | 3.4 · 실 I 의 근거로 보류 |

🔴 **U2 는 벤치의 안전 지표(확신 있게 틀린 답의 수)와 직결된다.**
`claims: []` 를 "없음" 으로 오독했던 사고가, `"아직 아무도 손대지 않았습니다"`
같은 평문 한 줄이면 구조적으로 일어나지 않는다.

어떤 것을 먼저 하든 **`docs/BENCH.md` 의 M3 를 앞당기는가**를 먼저 묻는다
(`app/web/shell.js` 머리말의 규칙).
