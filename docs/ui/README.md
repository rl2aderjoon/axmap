# UI 브레인스토밍

화면을 어떻게 만들지 **아직 정하지 않은 것들**이 사는 곳이다.

여기는 `docs/SPEC.md`(규격)도 `docs/DECISIONS.md`(내려진 결정)도 아니다.
그 둘은 **이미 정한 것**을 적는 곳이고, 여기는 **재보는 중인 것**을 적는 곳이다.
섞으면 다음 사람이 무엇이 확정이고 무엇이 아이디어인지 구분하지 못한다.

## 여기 있는 것이 밖으로 나가는 경로

```
docs/ui/IDEAS.md          떠오른 것을 한 줄로 쌓는다
      ↓  (근거가 생기면)
docs/ui/YYYY-MM-DD-*.md   실제로 열어 보고 재서 조사 기록을 남긴다
      ↓  (판단이 서면)
docs/DECISIONS.md         D 번호를 받는다. 버린 대안도 함께 적는다
      ↓
app/web/                  코드가 된다
```

🔴 **거꾸로 가지 않는다.** 코드를 먼저 짜고 여기에 사후 설명을 적으면
이 폴더는 낡은 지도가 된다 (CLAUDE.md §0.5).

## 조사 기록을 하나 추가할 때

파일 이름은 `YYYY-MM-DD-<대상>.md`. 날짜가 앞에 오면 폴더가 저절로 시간순으로 선다.

지켜야 할 것은 하나뿐이다.

> **기억으로 문장을 쓰지 않는다. 모든 주장에 출처를 붙인다.**

제품을 조사했으면 실제로 열어 보고 화면에서 읽은 것을 적는다.
우리 코드를 가리키면 파일과 줄을 적는다. 못 본 것은 "못 봤다"고 적는다 —
안 적으면 다음 사람이 그것도 확인된 것으로 읽는다.

문서의 첫 절은 **`0. 한 줄 결론`** 이다. 아래 표에 그 한 줄을 그대로 옮긴다.

## 지금까지

> 파일 목록은 여기 베끼지 않는다 — 폴더를 보면 된다.
> **한 줄 결론만** 적는 이유는, 그것이 파일 이름에서 읽히지 않는 유일한 정보이기 때문이다.
