# 쪽지 자동 수신 — 사용자가 명령하지 않아도 쪽지가 오게 한다

이 문서는 **쪽지함(bus)** 이 "물어봐야 보이는 것" 에서 "안 물어도 보이는 것" 으로
바뀐 과정과, 그렇게 정한 이유를 남긴다. 실측한 날짜는 **2026-08-27~28** 이다.

용어는 처음 나올 때 한 줄로 푼다 (팀 `CLAUDE.md` 0절).

> 🔴 **2026-10-29 · 팀 저장소 사본(`ci/axmap/`)을 폐기했다** ([D31](DECISIONS.md)).
> 아래 0·1·6절의 벤더링·핀·`verify-vendor` 이야기는 그 전의 기록이다. 지금은 장부와
> 코드가 axMap 한 곳에만 있고, 쪽지 도구는 `axmap bus …` 로 부른다. 6절의 구조적
> 결함(낡은 사본을 아무 검사도 못 알려준다)은 사본을 없애는 것으로 닫았다.

| 말 | 뜻 |
|---|---|
| **쪽지함(bus)** | 에이전트끼리 사람을 거치지 않고 주고받는 쪽지. 고아 브랜치 `axmap/bus` 에 실려 오간다 |
| **고아 브랜치** | 다른 커밋과 조상을 공유하지 않는 독립 브랜치. 작업 코드와 섞이지 않아 MR 없이 push/fetch 로 오갈 수 있다 |
| **worktree** | 같은 저장소의 다른 브랜치를 옆 폴더로 펼쳐 둔 것. 쪽지함은 `.axmap/bus` 다 |
| **읽음 표시** | "여기까지 봤다" 를 적어 두는 것. `.axmap-bus-seen.json` 에 사람별 고수위(가장 큰 id) 하나만 든다 |
| **폴링(polling)** | 새것이 있는지 주기적으로 물어보는 것. **바쁜 폴링**은 그 간격이 몇 초로 짧은 것 |
| **MCP** | Model Context Protocol — AI 도구가 외부 기능에 붙는 규격 |
| **훅(hook)** | 정해진 시점마다 하네스가 자동으로 실행하는 명령. 여기서는 **Claude Code 의 하네스 훅**을 말한다 (git 의 pre-commit 훅과 다른 것이다 — 아래 3.2 참고) |
| **벤더링(vendoring)** | 남의 코드를 내 저장소 안에 복사해 두고 그 사본으로 돌리는 것 |
| **핀(pin)** | 사본이 원본의 **어느 커밋**을 복사한 것인지. `ci/axmap/SOURCE.json` 의 `commit` |
| **종료 코드** | 프로그램이 끝나면서 내는 숫자. 0이면 성공, 그 외는 실패 |

## 0. 🔴 먼저 — 읽음 표시는 새로 만든 것이 아니다

이 작업을 시작할 때 증상은 *"`ax_inbox` 를 몇 번 불러도 안 읽은 23건이 그대로다"*
였다. **원인은 코드가 없는 것이 아니라 사본이 낡은 것이었다.**

| 자리 | 읽음 표시가 있나 |
|---|---|
| axmap `team-sync` (벤더 원본) | **있다.** `tools/bus.mjs` 의 `markSeen`·`readSeen`·`seen` 명령 |
| axmap `main` | **없다.** 아래 1절 |
| 팀 저장소 `origin/main` 의 사본 | **없다.** 핀이 `4556679`(2026-08-26)에 멈춰 있다 |
| 팀 저장소 `origin/chore/common/S15P21E201-25-bus-seen-marker` | **있다.** 핀 `3094659` 로 재벤더링된 채 MR 을 기다린다 |

실측으로 확인한 것:

```
$ git log --oneline 8d8c5ae..3094659          # -33 핀 → -25 핀 사이
3094659 판정을 못 했는데 통과시키고 있었다 — 경고 한 줄에 겹침 판정이 무너졌다
d60bf83 그린 쪽이 그린 것만 찍는다 — 접힌 쪽지가 화면에 뜬 적 없이 묻혔다
40acc38 읽음 표시를 실제로 찍는다 — 읽기만 하고 쓰는 곳이 없었다
c816ed6 쪽지 알림을 훅에서도 쓸 수 있게 한다 — 시계를 프로세스 밖으로
```

그리고 팀 브랜치의 사본과 벤더 원본이 **바이트 단위로 같다** — 즉 그 브랜치는
axmap `team-sync` 를 그대로 복사한 것이고, 손으로 고친 데가 없다.

```
$ diff <(git show origin/team-sync:tools/bus.mjs) \
       <(git show origin/chore/common/S15P21E201-25-bus-seen-marker:ci/axmap/tools/bus.mjs)
(차이 없음)
```

> 🔴 **그래서 읽음 표시를 다시 만들지 않았다.** 같은 것을 두 번 만들면 합칠 때
> 충돌만 남는다. 이 문서가 고친 것은 그 위에 남아 있던 결함 셋과 자동 수신이다.

### 0.1. 🔴 두 브랜치의 머지 순서가 중요하다 — `-33` 을 먼저, `-25` 를 나중에

팀 원격에서 사본을 갱신하는 브랜치가 지금 **둘**이고 핀이 다르다.

| 브랜치 | 핀 | 시각 |
|---|---|---|
| `chore/common/S15P21E201-33-ax-vote-commands` | `8d8c5ae` | 2026-08-27 06:07 |
| `chore/common/S15P21E201-25-bus-seen-marker` | `3094659` | 2026-08-27 08:18 |

`8d8c5ae` 는 `3094659` 의 **조상**이다 (`git merge-base --is-ancestor` 로 확인).
즉 `-25` 의 핀이 상위 집합이다. **`-25` 를 먼저 머지하면 그다음 `-33` 이
`SOURCE.json`·`manifest.sha256`·사본 파일을 옛 핀으로 덮어써서 위 커밋 넷이
통째로 되돌아간다** — 읽음 표시가 다시 사라진다.

`-33` → `-25` 순서로 머지하면 뒤에 오는 쪽이 상위 집합이라 아무것도 안 잃는다.

## 1. 🔴 `main` 이 아니라 `team-sync` 를 고쳐야 팀에 간다

axmap 저장소의 두 브랜치는 **조상을 공유하지 않는다.** 뿌리 커밋이 다르다.

```
$ git merge-base main origin/team-sync
(아무것도 안 나오고 종료 코드 1)

$ git rev-list --max-parents=0 main            → 9c2f9a1  (blastmap 초기 커밋, 161커밋)
$ git rev-list --max-parents=0 origin/team-sync → d40d3f2  (31커밋)
```

`ci/axmap/SOURCE.json` 의 `branch` 가 **`team-sync`** 이므로, 팀이 쓰는 것은
`team-sync` 뿐이다. `main` 에 고쳐 놓으면 **팀에는 영영 안 간다.**

> 🔴 두 갈래는 같은 파일(`tools/bus.mjs`·`mcp/server.mjs`)을 각자 갖고 있고,
> 지금까지 손으로 양쪽에 포팅해 왔다 (`main` 의 커밋 메시지에 "이 갈래에도" 가
> 반복된다). **이 작업의 변경도 `main` 에는 안 들어가 있다.** 아래 6절.

## 2. 지금 무엇이 어떻게 도는가

자동 수신은 **하나의 통로**로 돈다.

```
에이전트가 axMap 도구를 부른다  (ax_status·ax_claim·ax_check·ax_send·ax_brief …)
        │
        ├─ 도구가 자기 일을 한다
        │
        └─ mcp/server.mjs 의 unreadBanner() 가 결과 꼬리에 붙는다
                │
                ├─ tools/bus.mjs list --unread --no-mark --throttle N --quiet-if-empty
                │        └─ 창(N초)이 지났으면 git fetch, 아니면 로컬만 읽는다
                │
                ├─ 안 읽은 것이 없으면 → 아무 말도 안 한다 (빈 문자열)
                └─ 있으면 앞의 몇 줄을 그리고, 🔴 그린 것만 seen 에 찍는다
```

### 2.1. 왜 도구 결과에 얹는가

에이전트가 **확실히 읽는 것은 자기가 부른 도구의 결과뿐**이다. 그래서 그 자리에
붙인다. 무엇을 부르든 보인다. 이 방식은 이 작업이 만든 것이 아니라 이미 있던
것이고 (팀 `CLAUDE.md` 1절의 *"아무 도구를 불러도 결과 끝에 뜬다"*), **없애지
않고 그 위에 얹었다.**

### 2.2. 🔴 왜 바쁜 폴링을 하지 않는가

**이 알림에는 자기 시계가 없다.** 타이머로 도는 것이 아니라 에이전트가 도구를
부를 때만 돈다. 세션이 놀고 있으면 `git fetch` 도 0회다.

타이머로 돌리면 잃는 것이 셋이다.

1. 쪽지함은 고아 브랜치라 확인할 때마다 `git fetch` 가 원격에 나간다.
   **실측 (2026-08-27, `lab.ssafy.com`): 쪽지 브랜치 fetch 한 번이 0.77~0.84초.**
   3회 측정 — 827ms · 837ms · 774ms
2. 아무도 안 보는 새벽에도 원격을 두들기고 노트북 배터리를 먹는다
3. 알림을 받아도 **에이전트의 컨텍스트에 넣을 방법이 없다** — 3절

### 2.3. 왜 창이 15초인가

이 배너는 **도구 결과마다** 붙는다. 창이 없으면 에이전트의 **모든 도구 호출이
0.8초씩 느려진다.** 15초 창을 두면

- 한창 일하는 중에도 fetch 는 **분당 4회를 넘지 않는다**
- 0.8초를 무는 도구 호출은 그 창에 **한 번뿐**이다
- 새 쪽지는 **최악 15초** 늦게 뜬다

쪽지는 사람이 읽고 방향을 바꾸는 것이라 15초는 늦은 축에 못 든다. 급한 것은
`ax_claim` 의 `--intent` 에 한 줄로 적는 편이 여전히 빠르다 — 그건 `ax_status` 에
바로 보인다.

시계는 **프로세스 밖(스탬프 파일 `.axmap/.bus-lastfetch`)** 에 있다. 그래서 세션
내내 살아 있는 MCP 서버와, 부를 때마다 새 프로세스인 훅이 **같은 창을 나눠 쓴다.**
`fetch` 가 성공했을 때만 찍는다 — 실패에도 찍으면 원격이 잠깐 막힌 사이에 스탬프가
갱신되어 다음 창까지 조용히 안 받는다. 못 받은 것은 지연이지 성공이 아니다.

### 2.4. 🔴 없을 때 조용한 것이 알림의 조건이다

새 쪽지가 없으면 **한 줄도 안 찍는다** (`--quiet-if-empty`). 매 호출마다
"새 쪽지 0건" 을 찍으면 그 줄이 대화의 절반을 채우고, 사람은 곧 그 줄을 안 읽는다.
**그러면 진짜 쪽지가 왔을 때도 안 읽는다.** 반쪽짜리 알림은 없는 알림보다 나쁘다.

## 3. 🔴 MCP 가 스스로 알림을 보낼 수 있는가 — 규격을 확인했다

**답: 못 한다.** 추측이 아니라 규격과 클라이언트 문서를 확인한 결과다.

### 3.1. 규격에 있는 것과 없는 것

MCP 규격이 정의하는 서버→클라이언트 알림은 이것들이다.

| 알림 | 무엇을 위한 것인가 |
|---|---|
| `notifications/tools/list_changed` | 도구 목록이 바뀌었다 |
| `notifications/resources/list_changed` | 리소스 목록이 바뀌었다 |
| `notifications/resources/updated` | 구독한 리소스의 내용이 바뀌었다 |
| `notifications/message` | 로그. **2026-07-28 개정에서 폐기(deprecated)** |

🔴 **"모델의 대화 컨텍스트에 글을 넣는다" 는 목적의 규격 요소는 없다.** 위
알림들은 전부 **클라이언트 애플리케이션**에게 가는 것이고, 그것을 모델에게
보여줄지는 애플리케이션이 정한다. 규격 자신이 그렇게 못 박아 두었다 —
*"MCP focuses solely on the protocol for context exchange—it does not dictate how
AI applications use LLMs or manage the provided context."*

그리고 알림은 **구독이 먼저**다. 클라이언트가 구독 스트림을 열지 않으면 서버는
아무것도 먼저 보낼 수 없다.

Claude Code 쪽 문서에도 *"MCP 서버가 모델이 요청하지 않은 것을 보게 만드는
장치"* 는 없다. `notifications/message` 는 디버그 출력이지 모델 컨텍스트가 아니다.

> 근거:
> - <https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture>
> - <https://modelcontextprotocol.io/specification/2026-07-28/server/resources>
> - <https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/logging>
> - <https://code.claude.com/docs/en/mcp.md>

덧붙여, 이 서버는 애초에 그 통로를 열어 두지도 않았다 —
`mcp/server.mjs` 의 `initialize` 응답이 `capabilities: { tools: {} }` 뿐이다.
`logging` 도 `resources` 도 선언하지 않으므로, 규격상 그 알림을 보낼 자격이 없다.

**결론: 도구 호출에 얹는 지금 방식이 맞다.** 코드에 이미 적혀 있던 판단
(*"에이전트가 그것을 본다는 보장이 없다"*)이 규격 확인 후에도 그대로 성립한다.

### 3.2. 🔴 남은 구멍과 그 유일한 메꿈 — 하네스 훅

배너는 **axMap 도구를 한 번도 안 부르는 세션에는 영영 안 뜬다.** 그것이 이 방식의
구조적 한계다. 규격이 아니라 **하네스(harness — 에이전트를 돌리는 프로그램)** 만
그 구멍을 막을 수 있다.

Claude Code 에서 "매 턴 무언가를 돌려 그 출력을 모델 앞에 놓는" 장치는 **훅**이다.
모델이 실제로 보게 되는 출력을 낼 수 있는 훅은 셋으로 확인됐다.

| 훅 이벤트 | 언제 도는가 | 모델이 보는가 |
|---|---|---|
| `SessionStart` | 세션 시작·재개·compact 후 | **본다** |
| `UserPromptSubmit` | 사람이 프롬프트를 낼 때마다 | **본다** (기본 시간제한 30초) |
| `UserPromptExpansion` | 슬래시 명령이 프롬프트로 펼쳐질 때 | **본다** |
| `PostToolUse` · `Stop` 등 | — | 로그로만 간다 |

근거: <https://code.claude.com/docs/en/hooks-guide.md>

> 🔴 **여기서 말하는 훅은 git 의 `pre-commit` 훅이 아니다.** 이 저장소에는 이름이
> 같고 하는 일이 전혀 다른 것이 둘 있다. `setup.sh` 가 심는 것은 **git 훅**이고
> (claim 안 한 파일의 커밋을 막는다), 여기서 필요한 것은 **하네스 훅**이다.
> 실측: 두 저장소 어디에도 하네스 훅은 **설치되어 있지 않다.**
> `.claude/settings.json` 에 `hooks` 항목이 없고, `setup.sh` 는 git 훅만 심는다.

`tools/bus.mjs` 의 `--mine`·`--throttle`·`--quiet-if-empty` 는 **정확히 이 훅을
위해 만들어졌는데 (커밋 `c816ed6`), 정작 훅을 붙이는 쪽이 없다.** 붙이려면
`.claude/settings.json` 에 이렇게 넣으면 된다.

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "axmap bus list --mine --unread --throttle 60 --quiet-if-empty",
            "timeout": 20
          }
        ]
      }
    ]
  }
}
```

훅에서 창을 60초로 둔 이유: `UserPromptSubmit` 은 사람의 턴마다 도는데 사람의
턴은 보통 분 단위로 벌어진다. 그러니 창은 대개 의미가 없고, **연달아 프롬프트를
던지는 경우만 막는 하한**으로 있으면 된다. 그리고 이 훅의 기본 시간제한이 30초라
`fetch` 0.8초는 안전하지만, 창이 대부분의 호출에서 네트워크를 아예 안 타게
만들어 두는 편이 낫다.

> 🔴 **이 파일은 이 작업에서 만들지 않았다.** `.claude/settings.json` 은 팀
> 저장소의 파일이고 이 작업은 팀 저장소를 읽기만 하기로 했다. 그리고 훅을
> 심는 것은 `setup.sh` 의 일이라 **배포·설치 담당의 자리**다. 사람이 정할 것.

## 4. 설정 — 주기와 조건을 코드에 박지 않는다

| 설정 | 무엇을 정하나 | 기본값 | 어디서 읽나 |
|---|---|---|---|
| `AXMAP_BUS_POLL` | 원격을 다시 묻기까지의 **초** | MCP 배너 15 / CLI 직접 호출 0 | `mcp/server.mjs`, `tools/bus.mjs` |
| `AXMAP_BUS_ROWS` | 배너에 실제로 **그리는 줄 수**. **0 이면 배너를 끈다** | 3 | `mcp/server.mjs` |
| `--throttle <초>` | 그 호출에서만 창을 정한다. `AXMAP_BUS_POLL` 보다 우선 | — | `tools/bus.mjs` |

MCP 서버는 `.mcp.json` 의 `env` 로, 훅은 명령줄 `--throttle` 로 정한다.

**두 값은 서로 다른 것을 조절한다.** 줄 수는 **시끄러움**이고 주기는 **비용**이다.
줄 수를 줄이면 화면이 조용해지지만 원격을 묻는 횟수는 그대로이고, 주기를 늘리면
원격 부담이 줄지만 새 쪽지가 그만큼 늦게 뜬다.

두 가지 판단을 코드에 적어 두었다.

- **`AXMAP_BUS_ROWS=0` 은 `git fetch` 전에 나간다.** 안 그러면 그릴 것이 없는데
  네트워크만 타는 상태가 된다 — 껐는데 비용은 그대로인 것은 끈 것이 아니다
- **읽을 수 없는 값은 기본값으로 되돌린다** (`envNum`). 오타 하나로 배너가 조용히
  꺼지거나(`NaN < 1`) 매 호출마다 fetch 가 도는(`NaN → 0`) 쪽으로 가면 안 된다
- **`tools/bus.mjs` 의 기본은 0(매번 받아온다)으로 남겼다.** 이 파일을 손으로
  치는 사람은 지금 이 순간의 쪽지를 보려는 것이므로 캐시를 쥐여주면 안 된다.
  자동으로 자주 부르는 쪽이 자기 창을 명시한다

## 5. 함께 고친 결함 셋 — 전부 재현해서 확인했다

### 5.1. 🔴 자기가 보낸 전체공지를 자기 "안 읽은 쪽지" 로 세고 있었다

사용자가 본 증상: *"같은 시점에 `ax_status` 는 안 읽은 23건, `ax_send` 결과는
34건. 숫자가 다르다."*

원인은 **같은 것을 두 곳이 다른 규칙으로 센 것**이다.

| 세는 곳 | 내가 보낸 것을 뺐나 |
|---|---|
| `bin/axmap.mjs` 의 `unreadNotes` | **뺐다** — `if (from === me) continue` |
| `tools/bus.mjs` 의 `list --unread` | **안 뺐다** |

차이 11건은 전부 그 사람이 직접 보낸 **전체공지**였다. `to: all` 이라
`m.to === 'all'` 필터에 자기 것이 걸린다. 개인 쪽지에서는 안 드러난다 — `to` 가
남의 이름이라 애초에 안 잡히기 때문이고, 그래서 이 버그는 전체공지를 쓰기
시작한 날 나왔다.

고친 것: `rows.filter((m) => m.id > seen && m.from !== who)`.

### 5.2. 🔴 두 배너가 같은 것을 다른 이름으로 불렀다

| 어디 | 뭐라고 했나 | 실제로 무엇인가 |
|---|---|---|
| `bin/axmap.mjs` (CLI) | "안 읽은 쪽지 N건" | 안 읽은 수 |
| `mcp/server.mjs` (배너) | "**나에게 온** 쪽지 N건" | **역시** 안 읽은 수 |

한 사람이 한 화면에서 이름이 다른 두 숫자를 보면 *"하나는 전체고 하나는
미읽음인가?"* 를 묻게 되는데 **둘 다 미읽음이다.** 읽는 사람이 뜻을 물어야 하는
알림은 알림이 아니다. 배너를 "안 읽은 쪽지 N건" 으로 맞췄고,
`test/mcp.test.mjs` 가 그 문구를 고정한다.

### 5.3. 안내 경로가 칠 수 없는 문자열로 나왔다

`tools/bus.mjs` 의 `selfCmd()` 가 상대 경로를 무조건 썼다. 도구가 대상 저장소
밖에 있으면 이렇게 나온다 (실측):

```
총 4개. 본문:  node ../../../../../../../../../Desktop/git/axmap/tools/bus.mjs read <아이디>
```

"쪽지가 있다" 고 말한 **바로 그 줄**이 읽는 방법을 못 쓰게 알려준다. 받은 사람은
도구가 고장 났다고 결론짓는다. 둘 중 짧은 쪽을 쓰게 했다 — `bin/axmap.mjs` 의
`busReadHint` 가 이미 같은 판단을 하고 있었고, 이 파일만 안 하고 있었다.

## 6. 🔴 구조적 결함 — 낡은 사본은 어떤 검사도 알려주지 않는다

> ✅ **2026-10-29 에 닫았다** ([D31](DECISIONS.md)). 아래 제안(핀 최신성 검사)은 만들지
> 않는다 — 사본 자체를 걷어냈으므로 따라갈 핀이 없다. 기록으로 남긴다.

이 버그가 오래 살아남은 진짜 이유다. **아무 검사도 빨개지지 않았다.**

```
$ node ci/verify-vendor.mjs
사본이 해시 목록과 일치합니다: ci/axmap
  ... 17개 전부 ok
$ echo $?
0
```

`ci/verify-vendor.mjs` 는 사본의 **무결성**만 본다 — `manifest.sha256`(파일마다의
지문 목록)과 실제 파일이 맞는지. **핀이 최신인지는 설계상 보지 않는다.**
그래서 사본이 원본보다 8커밋 뒤처져 있어도 종료 코드는 0이고, 사용자 화면에만
"안 읽은 23건" 이 계속 떴다.

팀 규칙은 *"팀이 지키기로 한 것은 전부 CI 잡으로 만든다"* (`CLAUDE.md` 3절)인데
**여기 구멍이 하나 있다.** 지켜지는 것: "사본을 손으로 고치지 않았다".
안 지켜지는 것: "사본이 원본을 따라가고 있다".

### 제안 — 핀 최신성 검사 (사람이 판단할 것)

`ci/` 에 잡을 하나 더 두는 방식이 있다. 사본의 `SOURCE.json` 에 적힌 핀과
원본 브랜치의 머리를 대조하는 것이다 — `git ls-remote <axmap 저장소> team-sync`
로 머리를 얻고, 그것이 사본의 핀과 다르면 **몇 커밋 뒤처졌는지와 그 사이
커밋 제목들**을 낸다.

다만 판단이 갈리는 자리가 둘 있고, 이건 사람이 정해야 한다.

1. **실패로 만들 것인가, 경고로 둘 것인가.** 실패로 만들면 axMap 이 한 커밋
   나아갈 때마다 팀 파이프라인이 빨개진다 — 팀 코드는 한 줄도 안 바뀌었는데.
   그건 벤더링을 도입한 이유(`CLAUDE.md` 0.3절, *"axMap 이 잠깐 깨진 날 팀
   파이프라인이 빨개진다"*)를 정면으로 거스른다. **경고로 두면** 아무도 안 보는
   줄이 하나 더 늘 뿐이라는 이번 사고의 반복이 된다.
   중간 안: **뒤처진 커밋 수가 문턱을 넘거나 특정 라벨이 붙은 커밋이 그 사이에
   있을 때만** 실패로 만든다.
2. **네트워크를 타는 잡이 된다.** axMap 저장소 접근 권한이 만료된 날 이 잡이
   죽는데, 그건 다시 0.3절이 끊으려던 연결이다. 판정 불가와 뒤처짐을 **다른
   종료 코드로** 갈라야 한다 — 못 물어본 것을 "최신" 으로도 "낡음" 으로도 세지
   않는 것이 이 저장소의 규칙이다.

> 🔴 이 잡은 이 작업에서 만들지 않았다. 팀 저장소의 `ci/` 를 건드리는 일이고
> 정족수(quorum — 통과에 필요한 최소 찬성 표수) 2표가 필요한 경로다.

## 7. 정하지 못하고 남긴 것

### 7.1. 🔴 "다른 사람의 컨텍스트를 가져온다" 가 무엇인가 — 해석이 둘이다

사용자 원문: *"스스로 메시지나 **다른 사람의 컨텍스트**를 가져오게"*.
두 갈래로 읽히고, **어느 쪽인지 몰라서 구현하지 않았다.**

| 해석 | 무엇을 만들게 되나 | 값과 비용 |
|---|---|---|
| **A. 장부의 claim** — 누가 어떤 파일을 왜 잡고 있는지 (`.axmap/ledger`) | 배너에 "남의 claim 이 새로 생겼다/바뀌었다" 를 한 줄 얹는다 | 이미 `ax_status` 가 전부 낸다. **자동으로 얹으면 조용할 때가 거의 없다** — claim 은 쪽지보다 훨씬 자주 바뀐다. 2.4절의 "없을 때 조용해야 한다" 와 정면으로 부딪힌다. 그래서 "**바뀐 것만**" 을 정의해야 하는데, 그 정의가 이 작업의 나머지보다 크다 |
| **B. 남이 지금 무슨 작업을 하는지의 서술** — 의도·진행 상황 | 새 데이터가 필요하다. claim 의 `--intent` 한 문장으로는 부족하다 | 쪽지함이 이미 그 용도다. 새 통로를 만들기보다 "**방향을 바꿀 때 쪽지를 보낸다**" 를 규칙으로 두는 편이 싸다 |

**물어야 할 것:** A 라면 "새 claim 만" 인가 "claim 이 바뀔 때마다" 인가.
B 라면 쪽지로 충분한가.

### 7.2. 하네스 훅을 실제로 심을 것인가

3.2절의 구멍(axMap 도구를 안 부르는 세션)은 훅으로만 막힌다. 그 훅을
`setup.sh` 가 심게 할 것인지는 **배포·설치 담당과 겹치는 자리**라 손대지 않았다.
심는다면 `UserPromptSubmit` 에 `--throttle 60` 이 지금 판단이다.

### 7.3. `main` 갈래에 포팅할 것인가

1절대로 두 갈래는 조상을 공유하지 않고, 지금까지 손으로 양쪽에 포팅해 왔다.
이 작업의 변경은 **`team-sync` 에만** 있다. `main` 의 데스크톱 앱도 같은 쪽지함을
쓰므로 5.1(자기 전체공지를 세는 것)과 5.2(문구)는 거기서도 똑같이 틀릴 것이다.
**확인하지 않았다** — `main` 의 `tools/bus.mjs` 는 이 작업의 범위 밖이었다.

### 7.4. 배치에 매달린 테스트 하나

`test/gate.test.mjs` 의 *"저장소의 진짜 policy.json 이 성립한다"* 는
`REPO_ROOT = <axmap 루트>/..` 에서 `governance/policy.json` 을 읽는다. 즉 axmap 이
**팀 저장소 안(`<팀루트>/axmap/`)에 있을 때만** 통과한다. axmap 을 단독으로
clone 하면 실패한다. 실측으로 갈랐다 — 팀과 같은 배치를 임시로 만들어 돌리면
같은 테스트가 통과한다. 고치지 않았다. **이 작업이 만든 실패가 아니고**, 무엇을
기준으로 삼을지(단독 clone 도 지원할 것인가)는 이 문서의 주제가 아니다.

## 8. 어떻게 확인했는가 — 재현 절차

코드를 읽고 "될 것 같다" 로 끝내지 않았다. 이 버그가 그렇게 살아남았다.
임시 폴더에 **원격 하나와 clone 둘**을 만들어 실제로 주고받았다.

```
remote.git (bare)  ←  alice        원격 하나, 사람 둘
                   ←  bob          각자 axmap init 으로 쪽지함 worktree 를 만든다
```

| 시험 | 결과 |
|---|---|
| A. 읽음 처리 | bob 안 읽은 **4건 → 목록을 본 뒤 0건**. `.axmap-bus-seen.json` 에 고수위가 찍힌다 |
| **B. 음성 대조** | 읽음 표시 파일을 지우면 **다시 4건**. 검사가 실제로 문다 |
| C. 자기 전체공지 | alice 가 보낸 전체공지 1건 / alice 의 안 읽은 쪽지 **0건** (고친 뒤) |
| D. 두 배너 | `ax_check` "안 읽은 쪽지 4건" = `ax_status` "안 읽은 쪽지 4건" |
| E. 개인 대 전체 | `--to bob` 도착 · `--to` 생략(`to: all`) 도착 |
| F. `AXMAP_BUS_ROWS=0` | 배너 안 뜸 + **스탬프가 안 생김** = fetch 도 안 돌았다 |
| G. `AXMAP_BUS_ROWS=1` | 6건 → 5건. **그린 한 줄만** 읽음이 된다 |
| H. `AXMAP_BUS_POLL=3600` | 창 안에서는 새 쪽지를 안 받는다. 스탬프를 지우면 즉시 받는다 |
| I. 안내 경로 | `../../..` 가 사라지고 칠 수 있는 경로가 나온다 |
| J. 조용함 | 안 읽은 것이 0이면 한 줄도 안 찍는다 |

MCP 통로는 서버를 **stdio JSON-RPC 로 직접 몰아서** 확인했다 —
`initialize` 뒤에 `tools/call` 을 연달아 보내고 배너가 **4건 → 1건 → 안 뜸** 으로
줄어드는 것을 봤다. 코드 경로가 아니라 실제 응답 문자열이다.

### 판정

```
node tools/run-tests.mjs
```

이 문서를 쓴 시점(2026-08-28)의 실측: **종료 코드 1**. 남은 실패는 **7.4절의
배치 의존 테스트 한 건뿐**이고, 그건 이 작업이 만든 것이 아니다 — axmap 을
단독으로 clone 했기 때문에 나는 실패이며, 팀과 같은 배치를 임시로 만들어
돌리면 통과한다.

**통과 개수는 적지 않는다** — 적어 두면 테스트를 늘릴 때마다 그 줄이 낡고, 낡은
기준은 없는 기준보다 나쁘다 (팀 `CLAUDE.md` 4절). 판정은 종료 코드다.

쪽지 쪽만 따로 보려면 위 표의 A~J 를 그대로 돌리는 스크립트가 있다. 그것은
저장소가 아니라 임시 폴더에 있다 — 시험용 원격과 clone 둘을 만드는 스크립트라
저장소에 남길 것이 아니다.

### 9.1. 🔴 이 변경은 커밋되지 않았고, 같은 작업 폴더에 다른 작업이 함께 있다

작업은 `origin/team-sync` 를 detached(브랜치 없이 커밋을 직접 가리키는 상태)로
펼친 worktree 에서 했다. **커밋하지 않았다** — 올리는 것은 사람의 몫이다.

그 폴더에는 **배포·설치 작업이 동시에 들어와 있다.** 실측으로 가른 것:

| 누구의 것 | 파일 |
|---|---|
| 이 작업(쪽지) | `tools/bus.mjs` · `mcp/server.mjs` · `test/mcp.test.mjs` · `docs/BUS-NOTIFY.md` |
| 배포·설치 작업 | `bin/axmap.mjs` · `package.json` · `src/update.mjs` · `tools/setup.mjs` · `test/update.test.mjs` · `test/closure.test.mjs` · `.claude/` |

**겹치는 파일은 없다.** 다만 두 작업이 한 작업 트리에 섞여 있으므로,
커밋할 때 위 표대로 갈라서 담아야 한다. 한 커밋에 섞이면 나중에 하나만
되돌릴 수 없다.

> 🔴 이 상황 자체가 이 저장소의 선점 프로토콜이 막으려는 것이다. 두 작업 중
> 어느 쪽도 `ax_claim` 을 부르지 않았고, 그래서 같은 폴더를 함께 쓰는 것을
> 아무도 막지 않았다. 파일이 안 겹친 것은 **운이었다.**
