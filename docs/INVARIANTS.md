# 불변식 — 계획을 검사 가능한 문장으로

`README.md` 의 계획은 산문이다. 산문은 검증할 수 없다.
이 문서는 그 계획을 **언제나 참이어야 하는 성질**로 옮긴 것이고,
검증 도구들은 이 성질이 깨지는 순간을 찾는 것이 전부다.

버그를 "사건"이 아니라 "성질의 위반"으로 적어두면,
같은 종류의 버그가 다른 얼굴로 와도 걸린다.

---

## I1 · 상호배제

> 어느 시점에도, 서로 겹치는 경로를 유효하게 소유한 에이전트는 **최대 1명**이다.

```
∀t. ∀a,b ∈ active(claims, t). a.agent ≠ b.agent →
      ¬∃ p ∈ a.paths, q ∈ b.paths : overlap(p, q)
```

계획의 3번 — "겹치는 작업 방지" — 그 자체다. **이것 하나가 깨지면 프로젝트의 전제가 무너진다.**

## I2 · 무손실

> `claim` 이 성공을 반환했으면, 요청한 경로는 반드시 내 레코드에 들어 있다.

```
claim(requested) = ok(record) → requested ⊆ record.paths
```

"성공했다"는 응답을 믿을 수 있어야 한다. 성공했는데 장부에 없으면 에이전트는
자기가 선점했다고 믿고 작업하지만 아무도 막아주지 않는다.

## I3 · 진행성

> 활성 claim 과 겹치지 않는 요청은 **반드시 성공한다.**

```
¬blocked(requested, claims, me, t) → claim(requested) = ok
```

거짓 거부가 없어야 한다는 뜻이다. 6명이 붙어도 겹치지 않는 일은 굶지 않아야 한다.
관문 1(CAS)의 재시도 루프가 유한 횟수 안에 수렴하는 것도 여기에 포함된다.

## I4 · 회수

> 만료된 claim 은 **어떤 경로도 막지 못한다.**

```
expired(c, t) → ∀p ∈ c.paths. ¬blocks(c, p, t)
```

에이전트는 죽는다. 죽은 에이전트가 저장소를 영구히 잠그면 시스템이 멈춘다.

## I5 · 강제

> claim 하지 않은 파일은 **커밋되지 않는다.**

```
∀f ∈ staged. ∃p ∈ myActiveClaim.paths : f = p ∨ f ⊂ p
```

이것이 없으면 프로토콜은 권고 사항이다. 지키는 에이전트만 손해를 본다.

## I6 · 비부활

> 성공한 claim 의 경로는 **(요청한 경로 ∪ 직전 *유효* claim 의 경로)** 안에 있다.

```
after.paths ⊆ requested ∪ activeBefore(me).paths
```

실제로 발견된 버그를 성질로 옮긴 것이다.
`claim` 은 기존 claim 과 경로를 합집합으로 합치는데, 그 "기존"이 이미 만료된 내 것이면
그 사이 남이 정당하게 가져간 경로가 관문 2 를 거치지 않고 되살아난다.
**만료는 레코드가 사라지는 것이 아니라 효력만 잃는 것**이라는 구분을 놓치면 생긴다.

## I7 · 세션 이름 유일성

> 한 슬롯 레지스트리 안에서 **동시에 살아있는** 두 세션은 서로 다른 `AXMAP_AGENT` 를 갖는다.

```
∀ a,b ∈ live(registry). a.id ≠ b.id → a.agent ≠ b.agent ∧ a.agent ≠ ∅
```

**"모든 에이전트의 이름이 다르다" 는 여기에 적을 수 없다.** 사람이 두 셸에 같은
`AXMAP_AGENT` 를 넣으면 시스템이 막을 방법이 없고, 검사할 수 없는 문장을 불변식이라고
적어두면 이 목록 전체의 신뢰가 떨어진다. 시스템이 실제로 보장할 수 있는 것은
**자기가 띄운 세션들의 이름**뿐이므로, 그 범위로 좁혀서 적는다.

실제로 발견된 버그를 성질로 옮긴 것이다. `app/lib/session.mjs` 의 `spawn` 에 `env`
옵션이 없어서 자식이 서버의 환경을 그대로 물려받았고, 그래서 **앱에서 띄운 세션은
몇 개든 장부에서 한 사람**이었다. `checkOverlap` 은 자기 claim 을 겹침으로 보지
않으므로 그 세션들은 서로를 하나도 못 막았다 — I1(상호배제)이 판정 밖에서 무력화된
것이고, 여러 AI 세션을 동시에 굴린다는 이 앱의 목적과 정면으로 어긋난다.

`.mcp.json` 이 이름 없는 모두에게 `claude` 를 주던 그 실패(SPEC §3)와 같은 것이다.
그쪽은 이름을 **치환**해서, 이쪽은 이름을 **상속**해서 여러 사람이 한 사람이 됐다.

이름이 비어 있는 세션도 위반으로 센다. 이름이 없다는 것은 곧 서버의 이름을 물려받는다는
뜻이므로, 그것을 "위반 0" 으로 세면 이 검사기가 정확히 그 버그를 못 보게 된다.

## I8 · 게이트 우선

> 기계 게이트가 하나라도 빨갛거나 **빠진** 제안은 어떤 표 조합으로도 병합되지 않는다.

```
merged(p) → ∀g ∈ required. g ∈ gates(p) ∧ gates(p)[g].ok
```

I5(강제)와 같은 자리에 있다. I5 가 없으면 claim 이 권고 사항이 되듯,
I8 이 없으면 **게이트가 권고 사항이 된다.**

이 성질이 필요한 이유는 계획의 다음 단계에 있다 — 작업 노드가 사라져도 저장소가
스스로 굴러가게 하는 것. 그 구조의 실패 모드는 멈춤이 아니라 **조용한 부패**다.
아무도 안 볼 때 자동 워커가 빨간 것을 밀어 넣고, 그것을 아무도 모른다.

**안 돌린 게이트를 통과로 치지 않는 것**이 절반이다. 결과가 없는 것과 초록인 것을
같게 보면 게이트를 지우는 것만으로 I8 을 우회할 수 있다.

규격은 [SPEC.md](SPEC.md) §7-3.

## 어느 도구가 무엇을 확인하는가

**상태·전이 불변식(I1·I2·I6)은 같은 검사기(`src/invariants.mjs`)를 공유**한다.
도구마다 판정이 다르면 무엇이 맞는지 알 수 없게 되기 때문이다.

🔴 **I3·I4·I5 는 아직 공유되지 않는다.** 이 셋은 여러 프로세스가 실제로 돌아야
판정할 수 있어서 `demo/chaos.sh:144,154,171` 에 bash 로 따로 구현돼 있다.
즉 위 원칙이 절반만 지켜진 상태다 — 옮기기 전까지는 이 표를 믿을 때
"어디서 판정하는가" 열을 함께 봐야 한다.

🔴 **I8 은 아직 셋 중 어디에도 없다.** 병합 층의 git 연결이 없어서
`test/protocol.test.mjs` 의 단위 테스트로만 검사한다. 판정 자체는
`src/invariants.mjs` 의 `gatePrecedenceViolations()` 에 공유 검사기로 들어가 있으므로,
`axmap audit` 이 병합 기록을 읽게 되는 시점에 표의 세 번째 열이 채워진다.

| | 모델 검증기 | 카오스 테스트 | audit |
|---|:---:|:---:|:---:|
| | `test/model.test.mjs` | `demo/chaos.sh` | `axmap audit` |
| I1 상호배제 | ✓ | ✓ | ✓ |
| I2 무손실 | ✓ | | |
| I3 진행성 | ✓ | ✓ (bash) | |
| I4 회수 | ✓ | ✓ (bash) | |
| I5 강제 | | ✓ (bash) | |
| I6 비부활 | ✓ | | |
| I7 이름 유일성 | | | |
| I8 게이트 우선 | | | |
| **잡는 것** | 내가 생각 못 한 순서 | git·OS 가 만드는 순서 | 실제로 일어난 순서 |
| **속도** | 초당 수천 케이스 | 수십 초 | 커밋 수에 비례 |
| **재현성** | 씨드로 완전 재현 | 비결정론적 | 이력이 곧 증거 |

🔴 **I7 은 위 세 도구 어디에도 없다.** 세 도구는 전부 **장부**를 본다. I7 은 장부가
아니라 앱이 세션에 이름을 나눠주는 자리의 성질이므로, 모델 검증기의 연산 수열에도
장부 스냅샷에도 나타나지 않는다. 대신 두 군데서 검사한다.

| 어디서 | 무엇 |
|---|---|
| `app/lib/slots.mjs` 의 `acquire` | 슬롯을 나눠준 **직후** 검사하고, 위반이면 세션을 만들지 않는다 |
| `test/slots.test.mjs` · `test/session-identity.test.mjs` | 검사기 자체와, 자식이 정말 그 이름을 받는지 |

I5(강제)를 pre-commit 훅이 지키는 것과 같은 모양이다 — **성질이 성립하는 자리에서
막는다.** 검사기는 `src/invariants.mjs` 의 `sessionIdentityViolations` 이고, 다른
불변식과 같은 파일에 둔다. 도구마다 판정이 다르면 무엇이 맞는지 알 수 없게 되기 때문이다.

### 모델 검증기

씨드 고정 난수로 연산 수열을 만들고 매 단계마다 불변식을 검사한다.
깨지면 **씨드와 최소 재현 수열**을 출력하므로 고치기 쉽다.

겹침 판정에는 **독립적인 참조 구현(oracle)** 을 쓴다.
`checkOverlap` 으로 기대값을 만들면 `checkOverlap` 이 스스로를 검증하는 셈이 되므로,
경로를 `/` 로 쪼개 세그먼트 단위로 비교하는 다른 방식으로 다시 구현해 두 답을 대조한다.

### 카오스 테스트

진짜 프로세스 여러 개를 진짜 저장소에 붙이고 무작위로 claim·작업·죽음·우회를 시킨다.
모델이 볼 수 없는 것 — 실제 CAS 레이스, git 인덱스 경합, `--no-verify` 우회 — 을 잡는다.

### audit

장부 브랜치는 **모든 claim 변화를 커밋으로 기록한 완전한 감사 로그**다.
스냅샷을 순서대로 재생하면 I1 이 깨진 적이 있는지 사후에 증명할 수 있다.
**구현을 믿을 필요가 없어진다**는 것이 이 검사의 핵심이고, 팀 실사용에도 그대로 쓴다.

시간이 흐르는 것만으로는 겹침이 생기지 않는다(만료는 claim 을 없앨 뿐이다).
겹침은 claim 이 추가될 때만 생기고 claim 은 커밋으로만 추가되므로,
각 커밋 시점만 검사하면 전체 구간을 덮는다.

## 검증기 자체를 검증한다

**한 번도 실패하지 않는 검사기는 검사기가 아니다.**
각 검사기마다 "일부러 심은 위반을 실제로 잡는가"를 확인하는 테스트를 둔다.

`axmap audit` 은 CLI 를 우회해 겹치는 claim 두 개를 장부에 직접 심었을 때
해당 커밋과 소유 구간을 지목하고 종료 코드 4 를 반환하는 것으로 확인했다.

## 불변식을 추가할 때

1. 여기에 **왜 그 성질이 필요한지**와 함께 적는다. 계획의 어느 부분인지 밝힌다.
2. `src/invariants.mjs` 에 검사 함수를 추가한다. 순수 함수여야 한다.
3. 모델 검증기의 매 단계 검사에 넣는다.
4. **그 검사가 실제로 실패하는 케이스**를 테스트로 함께 넣는다.
