# 온보딩 평가 — 이 도구가 성공했는지 재는 법

## 왜 이 문서가 있나

이 도구의 목표는 **처음 보는 코드베이스를 빨리 이해하게 하는 것**이다.
그런데 그 목표는 만든 사람이 판정할 수 없다. 만든 사람은 이미 안다.

> 오래 본 사람에게는 모든 도구가 직관적이다.

그래서 판정을 **컨텍스트가 0인 관찰자**에게 맡긴다.
이 문서는 그 관찰을 매번 같은 방식으로 하기 위한 절차다.

---

## 절차

### 1. 관찰자를 만든다

**이 대화의 컨텍스트를 물려받지 않은 새 에이전트**여야 한다.
fork 로 띄우면 만든 사람이 아는 것을 그대로 물려받아 "신입"이 성립하지 않는다.

### 2. 대상을 **추첨한다**

```bash
node tools/pick-repo.mjs              # 무작위 언어·별 구간
node tools/pick-repo.mjs --lang go    # 언어 지정
node tools/pick-repo.mjs --list       # 지금까지 본 것
```

🔴 **두 가지 금지가 있다.**

| 금지 | 왜 |
|---|---|
| **우리 저장소를 대상으로 삼지 않는다** | 아는 코드로는 "처음 보는 코드를 이해시키는가"를 못 잰다 |
| **같은 저장소를 두 번 쓰지 않는다** | 두 번째부터는 도구가 아니라 기억을 재게 된다 |

한동안 axMap 자신과 immich 만 반복해서 봤는데, 그건 없애려던 편향을
다른 형태로 되살린 것이었다. 추첨기가 `docs/evaluated-repos.txt` 를 읽고
이미 본 것을 빼며, 뽑을 때마다 그 파일에 기록한다.

**별 1천~5만 구간에서 뽑는다.** 상위만 보면 매번 리액트·리눅스가 나오는데,
그런 저장소는 클론만 수십 분이고 대부분의 사람이 실제로 온보딩하는 규모와도 다르다.

`--filter=blob:none` 로 클론하므로 히스토리는 전부 온다. 다만 squash merge 만
쓰는 저장소에서는 공변경이 얇게 나온다 — 그것도 관찰 대상이다.

**우리 저장소를 볼 때는 목적이 다르다.** 그건 온보딩 평가가 아니라
자기 문서 점검이고, 회차로 세지 않는다.

### 3. 과제를 준다 — 매번 같은 것

읽기만 시키지 않는다. **실제로 수행**하게 한다.

1. **이 프로젝트가 무엇인지 세 문장으로.** 그 결론에 닿기까지 파일 몇 개를 읽었는지 센다.
2. **실행하라.** 테스트·데모·앱. 각 단계에서 **첫 시도가 성공했는지** 기록한다.
3. **작은 변경을 어디에 해야 하는지 찾아라.** 그 답을 어떻게 알아냈는지, 확신하는지.
4. **이 프로젝트가 지키기로 한 성질이 무엇인지.** 하나를 어기면 무슨 일이 생기는지.
5. **도구가 1~4에 실제로 도움이 됐나.** 안 됐으면 안 됐다고.

### 4. 보고 규칙 — 이게 절차의 핵심이다

> **칭찬 금지.**

좋은지가 아니라 **어디서 막히는지**를 알아야 한다. 반드시 받는다:

- **막힌 지점 전부** — 몇 번 시도했는지, 무엇을 추측해야 했는지
- **틀리게 이해한 것** — 그리고 무엇이 오해하게 만들었는지
- **모순** — 서로 다른 말을 하는 문서·코드·주석
- **없어서 아쉬웠던 것**
- **읽는 순서** — 안내가 있나, 있다면 하나인가
- **도구가 도움이 됐나** — 구체적으로 어느 순간에

각 항목에 **파일명과 줄 번호**를 요구한다.
"문서가 부족하다"는 쓸모없다. "`README.md:9` 가 이 문서는 낡았다고 하면서 어디를 읽으라는지는 안 알려준다"가 쓸모있다.

마지막에 **우선순위 목록** — 신입 시간을 많이 먹은 순 × 고치기 쉬운 순.

### 5. 관찰자는 수정하지 않는다

관찰 대상이 관찰자를 고치면 측정이 아니다.
고치는 것은 메인 세션이 한다.

## 이 평가가 재지 못하는 것

정직하게 적는다.

- **한 명의 관찰**이다. 그 사람이 유별나게 막혔을 수도, 유별나게 잘 풀었을 수도 있다.
- **에이전트는 사람이 아니다.** 지치지 않고, 부끄러워하지 않고, grep 이 빠르다.
  사람이 막히는 자리와 다를 수 있다.
- **처음 한 번만 잰다.** 이틀째·일주일째의 마찰은 안 잡힌다.
- **막힌 것만 센다.** 도구가 있어서 **안 생긴** 마찰은 셀 수 없다.
  ("이게 없었으면 얼마나 더 걸렸을까"는 반사실이라 측정 불가)

그래서 이 평가는 **개선의 방향**을 주지 **품질의 절대값**을 주지 않는다.
회차 간 비교로만 쓴다.

## 공개 주소에 올린다

평가는 **남이 보고 판단할 수 있어야** 평가다. 뽑은 저장소는 곧바로 공개 주소에 올라간다.

🔴 **지금 공개 주소는 없다.** `i15e101.p.ssafy.io` 는 반환됐다. 아래 절차는
새 서버를 받으면 다시 쓸 것이고, 그때까지 게시는 **이 PC 안에서만** 확인한다.

추첨기가 클론을 마치면 `tools/serve-public.mjs` 를 자동으로 부른다.
따로 띄우고 싶으면:

```bash
node tools/serve-public.mjs <경로|git주소> --auth 아이디:비밀번호
node tools/serve-public.mjs --status     # 지금 무엇이 올라가 있나
node tools/serve-public.mjs --stop
```

🔴 **추첨과 게시를 붙여둔 이유.**

떼어놓으면 두 가지가 어긋난다 — 새 저장소를 보고 있는데 **밖에서는 지난
저장소가 계속 보이고**, 손으로 띄우다 인증을 빠뜨린다.

🔴 **인증 없이는 올라가지 않는다 (fail-closed).**

7901 번은 공개된 자리다. `--readonly` 는 쓰기를 막는 것이지 보기를 막지 않는다.
자격증명이 없으면 띄우지 않고 종료한다. 기본값도 주지 않는다 —
기본 비밀번호는 비밀번호가 아니다.

올린 뒤에는 인증이 **실제로 걸렸는지** 확인하고, 401 이 아니면 즉시 내린다.
"걸었다고 믿는 것" 과 "걸린 것" 은 다르다 — 실제로 게이트가 라우트 뒤에 있어서
화면과 `/api/graph` 가 인증 없이 나가던 적이 있다.

🔴 **밖으로 나가는 통로가 지금은 없다.** 예전에는 로컬이 정상인데 공개가 502 이면
SSH 역터널이 끊긴 것이었다. 새 서버를 받으면 그 통로부터 다시 만든다.
