# 설계 결정 기록

## D29 · 일반 협업 메시지는 안전한 작업 경계에서 묶음 회수한다

**2026-10-27 · 사용자 요청.** 야간 보관본에서 진행 알림·과거 요청의 지연 전달이 반복
대조·ACK 턴을 만드는 문제를 확인했다. 일반 알림은 모델을 호출하지 않는 로컬 큐로 받고,
수신자가 테스트·실험 종료 등 명시한 작업 경계에서 한 번에 처리한다. 긴급 중단·데이터
손상·현재 작업 무효화만 발신자가 즉시 전달 사유를 명시한다. 현재 연결은 강제 interrupt를
지원하지 않으며 busy/불명 상태를 성공으로 보고하지 않는다. 같은 발신자의 대기 업데이트만
주제별로 대체하고 만료·전송불명·출처를 보존한다. [받은 편지함 규격](SESSION-MAILBOX.md).

현재 CLI·MCP 협업에 적용되는 결정이다. 프로토콜은 [SPEC.md](SPEC.md), 검증할 성질은
[INVARIANTS.md](INVARIANTS.md), 진행 중인 작업은 [THREADS.md](THREADS.md)를 따른다.
결정 번호는 기존 참조를 위해 유지한다.

## D4 · 결정론적 판정에 LLM을 넣지 않는다

경로 겹침, 만료, 소유권과 병합 가능 여부는 코드로 판정한다.
모델이 답하지 못하거나 잘못 답해도 선점·검증 기준이 달라져서는 안 된다.
읽기 실패와 데이터 없음을 구분하고, 판단할 수 없는 상태는 성공으로 처리하지 않는다.

## D18 · 합의제 MR의 표는 Git에 기록한다

병합 요청의 표는 `axmap/votes` 브랜치의 파일에 기록한다. 외부 서비스의 Approve 상태를
판정 기준으로 사용하지 않는다. 저장소를 옮겨도 표와 근거가 함께 남아야 하기 때문이다.
이 기능은 모든 우회를 차단하는 장치가 아니라, 판정과 우회 기록을 남기는 장치다.
정책과 한계는 [거버넌스 규격](../governance/GOVERNANCE.md)을 따른다.

## D20 · 과반 기준에서 작성자를 제외한다

정책 명단에서 병합 요청 작성자를 뺀 인원을 분모로 사용한다.
인원이 바뀔 때마다 사람이 고정 숫자를 수정하지 않도록 한다.
작성자나 명단을 확인하지 못하면 판정 불가로 종료한다. 기계 게이트가 실패하거나 빠진 경우
표가 충분해도 병합 가능으로 판정하지 않는다.

## D21 · CLI 협업 도구에 집중한다

**2026-10-13.** 경로 선점·상태·갱신·반납, 커밋 훅·감사, 설치·설정과 MCP가 제품의 중심이다.
설치한 사용자가 Git 저장소에서 바로 협업할 수 있어야 한다.

## D22 · 작업 repo를 세션별로 따라가고 장부를 자동 준비한다

**2026-10-15 · 1.3.0.** 조회·선점 명령은 장부가 없으면 준비하고 원래 요청을 계속한다.
기존 원격 장부를 이어 쓰며, 원격에 없다고 확인된 경우에만 새 고아 브랜치를 만든다.
원격 접근 실패나 모호성을 빈 장부로 바꾸지 않는다.

대상 선택 순서는 `AXMAP_REPO` → 도구의 절대 경로 `cwd` → MCP roots → 시작 폴더다.
roots가 모호하거나 읽히지 않으면 이전 대상을 임의로 사용하지 않는다.
대상이 바뀌면 이전 repo에서 해당 세션의 claim만 반납한다. 이름은 세션 동안 유지한다.

동시 준비는 Git 공통 디렉터리의 잠금으로 직렬화한다. 연결된 worktree들은 장부를 공유한다.
자동 준비는 장부만 만들며 커밋 훅은 `hook install`로 명시한다.

## D23 · setup은 PC 전역 설정이다

**2026-10-15 · 1.3.1.** setup은 Git 밖을 포함한 어느 폴더에서든 실행한다.
기본 설치는 실행 폴더에 대상을 고정하거나 장부·커밋 훅을 만들지 않는다.
`--repo`, `--remote`, `--commands project`로 명시한 경우에만 특정 프로젝트를 준비한다.

이름의 기본값은 전역 Git 설정에서 읽는다. MCP 등록은 실제 서버 경로·환경·cwd를 확인해
오래된 설정을 갱신하며 개인 환경값과 다른 서버를 보존한다. 읽지 못한 설정은 덮어쓰지 않는다.

## D24 · 표시 이름과 repo 참여 정보를 자동 공유한다

**2026-10-16 · 1.3.2.** setup은 표시 이름을 저장하고 재설치 때 유지한다.
Git 이름·이메일과 선점 신원은 바꾸지 않는다. 이메일은 실제 작업 repo에서 읽는다.

해당 repo를 실제 사용할 때 `axmap/users`에 표시 이름을 공유한다. setup만으로 등록하지 않는다.
확인된 수신자는 이메일로 저장하고 동명이인은 자동 선택하지 않는다.
공유 실패는 경고·재시도하며 투표 권한을 부여하지 않는다. 사용자 상태는 공통 디렉터리 잠금으로
직렬화하고 읽음 기록과 게시되지 않은 프로필을 버리지 않는다.

## D25 · 사용하지 않는 제품 영역을 소스에서 제거한다

**2026-10-18 · 사용자 요청.** 코드 시각화·데스크톱 화면·분석 코퍼스와 그 전용 도구·테스트·문서를
제거한다. CLI 설치에 필요한 공용 기능만 `src`에 둔다. 과거 소스는 Git 이력에서 확인한다.
README는 간략한 소개·설치 다음에 버전별 변경 기록을 배치한다.

로컬 세션 연결은 개발 중이다. [SESSION-BRIDGE.md](SESSION-BRIDGE.md)의 검증 상태를 유지하고,
실제 CLI 연결이 확인되기 전에는 공개 버전의 동작으로 소개하지 않는다.

## D26 · 관리형 세션의 자동 소통과 사용량을 함께 추적한다

**2026-10-20 · 사용자 요청.** Codex와 Antigravity 사이의 자동 왕복 소통을 다음 릴리스에 제공한다.
`bridge serve`로 사용자가 명시적으로 시작한 Codex App Server와 agy stream-json 프로세스를
유지한다. 이미 열린 임의의 터미널에 붙거나, 전달 실패를 숨기고 새 모델 프로세스를 만들지 않는다.

대기·중계·예산 검사는 코드가 수행하고 빈 큐 때문에 모델을 부르지 않는다. 각 세션이 자기
대화 맥락을 보유하므로 상대의 짧은 최신 메시지만 전달한다. 응답 JSON의 `done`으로 종료하고,
횟수·길이·처리 토큰 한도로 추가 실행을 막는다. 도구 실행 권한이나 사용자 승인은 자동 우회하지 않는다.

토큰은 CLI 누적 카운터의 차이로 계산한다. 캐시·추론은 포함 관계를 표시하며 중복 합산하지 않는다.
사용량이 없으면 0으로 간주하지 않고 중계를 중단한다. 토큰 한도는 실행 전 검사이며, 실행 중인
한 요청의 엄격한 상한이나 요금 추정치가 아니다. 검증 조건·실측·제한은 `SESSION-BRIDGE.md`에 기록한다.

## D27 · 실행 중인 요청 흐름을 터미널에서 관측한다

**2026-10-26 · 사용자 요청.** `axmap monitor`로 세션·요청·자동 대화·선점과 최근 상태 변화를
계속 표시한다. 접수·전달·응답 대기·완료 확인을 구분하고, 전송 불명과 승인 대기를 드러낸다.
표시는 실제 로컬 기록과 연결 확인에 기반하며 확인되지 않은 진행률이나 모델 내부 작업을
추정해 그리지 않는다. 관측 때문에 모델을 호출하거나 작업을 재전송·승인하지 않는다.
수집과 화면 애니메이션을 분리하고, 종료할 때 원래 터미널 화면을 복원한다.

## D28 · 현재 대화에서 클라이언트 기능에 맞게 흐름을 표시한다

**2026-10-26 · 사용자 요청.** 별도 모니터 대신 ChatGPT·Claude·agy의 현재 대화에서 진행을
확인할 수 있게 한다. 공통 상태 데이터에 MCP Apps 패널, 표준 진행 알림, Claude Code·agy
상태줄을 연결한다. 기능은 호스트의 지원 선언으로 판단하며 클라이언트 이름으로 추측하지 않는다.
기존 상태줄과 설정을 보존하고 제거 시 복원한다. 관찰 취소는 작업 취소나 재전송을 뜻하지 않는다.
계약 테스트와 실제 클라이언트 검증을 구별한다. 설치와 검증 범위는
[PIPELINE-CLIENTS.md](PIPELINE-CLIENTS.md)에 기록한다.
