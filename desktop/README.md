# axMap 데스크톱 셸

`app/server.mjs` 를 띄우고 창으로 가리키는 것이 전부다.
**화면도 분석도 여기 없다** — 전부 `app/` 과 `src/` 에 그대로 있다.

배경과 버린 대안은 [docs/DECISIONS.md](../docs/DECISIONS.md) 의 **D16**.

---

## 쓰는 법

```bash
cd desktop
npm install          # 여기서만 의존성이 생긴다. 루트는 계속 0 개다
npm start            # 앱 실행 — 처음에는 저장소를 고르는 창이 뜬다
npm run selftest     # 화면이 실제로 그려지는지 확인, exit 0/1
npm run dist         # 아이콘 → 빌드 → 바탕화면 바로가기. 아래 참고
```

저장소 루트에서:

```bash
npm run desktop      # 소스로 실행
npm run dist         # 빌드 (= desktop 의 dist)
npm run shortcut     # 빌드 없이, 소스를 가리키는 바로가기만 새로 만든다
```

## 빌드하면 바탕화면 아이콘이 갱신된다

`npm run dist` 는 세 가지를 순서대로 한다.

| | |
|---|---|
| `tools/make-icon.mjs` | `build/icon.ico` 를 **코드로 그린다** (16~256px 6종). 저장소에 바이너리를 안 넣으려는 것이고, 모양은 트레이 아이콘과 같은 궤도 표식이다 |
| `electron-builder` | `dist/win-unpacked/axMap.exe` 와 설치본 `dist/axmap-setup-<버전>.exe` |
| `tools/shortcut.mjs` | 바탕화면 바로가기를 만들고 **같은 자리를 덮어쓴다** |

🔴 **바로가기 이름을 버전으로 나누지 않는다.** `axMap 0.0.2` 처럼 만들면 바탕화면에
낡은 아이콘이 쌓이고 사람은 그중 아무거나 누른다 — 어제 고친 버그가 살아 있는 화면을
보면서 도구를 탓하게 된다는 뜻이다. 이름을 고정해서 **"바탕화면의 그 아이콘 = 마지막
빌드"** 가 항상 참이게 한다.

🔴 **바탕화면 경로를 `%USERPROFILE%\Desktop` 으로 짐작하지 않는다.** OneDrive 를 쓰면
`...\OneDrive\바탕 화면` 으로 옮겨 가 있다. 짐작하면 아무도 안 보는 자리에 파일을
만들어 놓고 성공했다고 말하게 된다. 윈도우에게 직접 묻는다.

🔴 **바로가기 이름은 언제나 `axMap 실행` 이다.** 저장소가 바탕화면에 있으면 `axmap`
폴더와 `axmap` 바로가기가 나란히 뜨는데, 윈도우가 `.lnk` 를 감추므로 **둘 다 "axmap"
으로 보인다.** 겹칠 때만 비키게 하면 이름이 기계마다·저장소 위치마다 달라져서 이
문서도 옆자리에 하는 말도 누군가에게는 틀린 말이 된다. 그래서 조건 없이 한 이름이다.

특정 저장소를 바로 열려면:

```bash
npm start -- --target=C:/path/to/repo
```

## 지켜야 하는 것 하나

> **import 방향은 `desktop/` → 코어 단방향이다.**
> `src/*` 와 `app/*` 는 Electron 을 import 하지 않는다.

이것만 지키면 나머지(번들링·서명·오프라인 빌드)는 나중에 전부 **설정으로** 풀린다.
역방향이 한 번이라도 생기면 그때부터는 떼어내는 것이 진짜 작업이 된다.

그래서 이 셸은 코어를 `import` 하지 않고 **자식 프로세스로 띄운다.**
덕분에 `node app/server.mjs` 로 브라우저에서 여는 길이 그대로 살아 있고,
AWS 에 올린 공개 뷰어도 같은 코드를 쓴다.

## 상주형이다

**창을 닫아도 앱은 안 죽는다. 숨을 뿐이다.**

Electron 이 네이티브에 지는 유일하게 체감되는 지점이 콜드 스타트(Chromium 초기화 1~3초)인데,
그 비용은 프로세스를 살려두면 **앱 수명에 한 번만** 내면 된다. 게다가 서버가 이미 저장소를
다 읽어둔 상태도 함께 살아 있다 — 큰 저장소는 다시 띄우면 수십 초를 다시 기다려야 한다.

부르고 끝내는 길:

| | |
|---|---|
| 부르기 | 컴패니언 단축키, 또는 트레이 아이콘 클릭 |
| 저장소 바꾸기 | 트레이 메뉴, 또는 `저장소 › 다른 저장소 열기` |
| 진짜 끝내기 | 트레이 메뉴의 `종료`, 또는 `저장소 › 종료` |
| 로그인 시 자동 실행 | 트레이 메뉴의 체크박스. `--hidden` 이 붙어 창 없이 뜬다 |

자동 실행인데 기억해 둔 저장소가 없으면 **아무것도 묻지 않고 끝낸다.**
부팅하자마자 폴더 고르는 창이 튀어나오는 것만큼 확실하게 미움받는 동작이 없다.

## 정지한 화면은 다시 안 그린다

`app/web/graph.js` 가 배치가 멈추면 그리기를 늦추거나 아예 멈춘다. 측정값:

| | 초당 그리기 |
|---|---|
| 이전 | 120회 |
| 지금 · 흐르는 점만 움직임 | 19회 |
| 지금 · 아무것도 안 움직임 | 0회 (rAF 를 안 건다) |

`npm run selftest` 가 이 값을 재고 25회를 넘으면 **실패한다.**

🔴 이 검사는 처음에 **거짓으로 통과했다.** 자체 점검이 창을 안 띄웠고, 크로미움은
숨긴 창의 rAF 를 초당 1회로 줄인다. 그래서 정지 로직을 옛날 것으로 되돌려 놓고 돌려도
그대로 통과했다. 지금은 `showInactive()` 로 창을 띄우고 잰다 —
**자체 점검을 돌리면 창이 잠깐 뜬다. 버그가 아니다.**

## 알아둘 것

**`ELECTRON_RUN_AS_NODE=1`** — 서버를 띄울 때 이 변수를 준다. 그러면 `electron.exe` 가
크롬을 띄우지 않고 평범한 node 로 동작한다. **사용자 PC 에 Node 가 없어도 된다는 뜻**이고,
설치본에 런타임을 따로 싣지 않아도 되는 이유다.

**preload 는 `.cjs` 다.** 이 패키지는 `"type": "module"` 이라 `.js` 는 ESM 으로 읽히는데,
Electron 의 ESM preload 는 샌드박스를 꺼야만 동작한다. 확장자를 바꾸면 **조용히** 안 뜬다.

**종료할 때 `taskkill /T` 를 쓴다.** 윈도우에서 `child.kill()` 은 손자 프로세스(git)를
안 죽인다. 트리째 죽이지 않으면 포트를 문 채로 남아 다음 실행이 막힌다.
`tools/smoke.mjs` 와 같은 처리다.

**컴패니언 단축키는 후보를 내려간다.** `Alt+Space` → `Alt+Shift+Space` →
`Control+Shift+Space` → `Control+Shift+B` 순으로 시도하고, 잡힌 것을 콘솔과
`도움말` 메뉴에 적는다. `Alt+Space` 는 윈도우 시스템 메뉴 기본값이고 ChatGPT 앱이
깔려 있으면 그쪽이 먼저 쥔다. 등록 실패는 예외가 아니라 `false` 라 **조용히** 실패한다.

## 아직 안 한 것

- **코드 서명.** 실측으로 확인했다 — 빌드 로그에 `signing with signtool.exe` 가 찍히지만
  인증서가 없어서 `Get-AuthenticodeSignature` 는 **`NotSigned`** 를 돌려준다.
  로그만 보고 서명됐다고 여기면 안 된다. 서명 없는 exe 는 SmartScreen 경고를 띄우고,
  그 경고는 발표 당일 남의 노트북에서 뜬다.
  **폐쇄망 보류 항목과 같은 바구니에 넣지 않는다** — MVP 안이다.
- **자동 업데이트.** electron-updater 는 아직 안 붙였다.
- **오프라인 빌드.** `npm ci` 만 네트워크를 쓰는 것이 아니다 — electron-builder 가
  Electron 바이너리를 GitHub Releases 에서 받아온다. 인터넷 되는 PC 에서 exe 를 만들어
  exe 를 반입하는 것이 지금의 답이다 (D16).
