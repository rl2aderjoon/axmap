# axMap MCP 서버

**MCP**(*Model Context Protocol* — **AI 도구가 바깥 프로그램을 "도구" 로 불러 쓸 수
있게 하는 규격**)로 axMap 을 AI CLI 에 붙인다.

- 붙이면 AI 도구가 **"나는 이 파일들을 건드리겠다"를 선언**하게 된다. 겹치면 그 자리에서 거부당한다
- 코드 충돌이 나기 전에 **의도 충돌**을 먼저 터뜨리는 것이고, 다른 에이전트는 그 선언을 읽어 작업 범위를 조정한다
- **한 번 설치하면 아무 저장소에서나 붙는다.** 작업할 저장소에는 파일을 하나도 남기지 않는다

---

## 설치

Node 20 이상과 git이 필요하다. Git 저장소 밖을 포함해 어느 폴더에서든 실행한다.

```bash
npm install -g axmap-cli@latest
axmap setup
```

어느 폴더에서든 setup을 실행한 뒤 AI CLI를 다시 시작한다. `setup`은 PC 전역에 MCP와 명령을 설치·등록하며 repo를 초기화하거나 타겟으로 저장하지 않는다. 이후 AI CLI를 켠 repo에서 장부를 자동 준비한다. 소스 개발 환경에서는 `node bin/axmap.mjs setup`을 사용한다. 명시적 repo 준비는 `setup --repo <경로>`를 사용한다.

AI에게 설치를 맡기려면 다음 공개 문서를 제공한다.

https://github.com/rl2aderjoon/axmap/blob/main/mcp/SETUP-FOR-AI.md

기존 소스 복사 설치기는 `mcp/install.ps1`과 `mcp/install.sh`에 있다. 일반 설치와 설정은 [INSTALL.md](../docs/INSTALL.md)를 따른다.

## 도구

| 도구 | 언제 |
|---|---|
| `ax_brief()` | 이 저장소에서 처음 일할 때 **가장 먼저** |
| `ax_status()` | 지금 누가 어디를 잡고 있나 |
| `ax_check(paths)` | 내가 건드릴 곳이 비었나 — **선언은 안 한다.** 계획 세울 때 |
| `ax_claim(paths, intent, task?)` | **파일을 고치기 전에 반드시.** intent 는 사람이 화면에서 읽는다 |
| `ax_release(paths?)` | 끝나면 즉시. 생략하면 전부 반납 |
| `ax_renew()` | 길어지면 시간 연장 |
| `ax_inbox(id?)` | 다른 에이전트가 나에게 보낸 쪽지를 읽는다 |
| `ax_sessions()` | 같은 repo의 연결된 세션·역할·상태·사용량 |
| `ax_dispatch(to, prompt)` / `ax_result(id)` | 연결된 세션에 단일 작업 전달·결과 조회 |
| `ax_chat(left, right, prompt, maxTurns?, maxTokens?)` | 관리형 세션 두 개의 제한된 자동 대화를 백그라운드 접수 |
| `ax_dialogue(id)` / `ax_chat_stop(id)` | 대화·토큰 조회 / 추가 중계 중단 |
| `ax_send(to?, subject, body)` | 다른 에이전트에게 쪽지를 보낸다 |
| `ax_init(remote?)` | 명시적 준비용. 조회·선점은 장부를 자동 준비하므로 먼저 부를 필요가 없다 |

`ax_claim` 이 거부되면(겹침) **재시도하지 말고 다른 작업으로 옮겨야 한다.**
같은 요청은 몇 번을 보내도 같은 답이 온다. 메시지에 점유자·작업·남은 시간이 들어
있으니 그걸 읽고 비어 있는 다른 곳으로 간다. 도구 설명에도 그렇게 적어두었다.

Claude Code 에서는 `/ax`, `/ax-start`, `/ax-done`, `/ax-tell` 로도 부른다 —
다만 그 슬래시 명령은 이 저장소의 `.claude/commands/` 에 들어 있어서 **이 저장소를
열었을 때만** 뜬다. 다른 저장소에서는 위 도구 이름을 문장으로 부르면 된다.

에이전트에게 줄 지시문은 이 셋이면 충분하다.

```
파일을 수정하기 전에 ax_claim 으로 건드릴 경로를 선언하라.
거부되면 재시도하지 말고 겹치지 않는 다른 작업으로 옮겨라.
작업이 끝나면 ax_release 를 호출하라.
```

## 원리와 실측

### 어느 CLI 에 어떻게 붙나

전송이 표준(stdio + 줄바꿈 JSON-RPC 2.0)이라 **MCP 를 지원하는 클라이언트면 무엇이든
붙는다.** 갈리는 것은 "자동으로 붙느냐" 뿐이다.

| CLI | 설정 파일 | 누가 넣나 | 확인했나 |
|---|---|---|---|
| Claude Code (`claude`) | `~/.claude.json` 의 user 범위 (**이 PC 의 모든 폴더에 적용되는 개인 설정**) | 설치기가 `claude mcp add -s user` 로 | ✅ 이 PC 에서 확인 |
| Claude Code (`claude`) | 저장소의 `.mcp.json` | 저장소에 들어 있으면 스스로 발견 | ✅ 이 저장소가 그렇게 쓴다 |
| Antigravity (`agy`) | `~/.gemini/config/mcp_config.json` (전역, `mcpServers`) | `tools/mcp-register.mjs` | ✅ `agy` 1.1.10 으로 확인 |
| Codex (`codex`) | `~/.codex/config.toml` (전역, `[mcp_servers.axmap]`) | `tools/mcp-register.mjs`가 Codex CLI로 등록·검증 | 임시 사용자 환경에서 실제 CLI 등록과 repo별 MCP 실행 확인 |

`agy` 에서 확인한 것: 전역 파일은 먹고, 저장소의 `.mcp.json` 은 **안 먹는다.**
공식 문서의 작업 폴더용 `.agents/mcp_config.json` 도 CLI 에서는 안 먹었다(IDE 쪽으로 보인다).
일부러 없는 파일을 가리키면 도구가 사라지는 것까지 확인했다 — 위 결과가 캐시가 아님을
보인 대조군이다.

**CLI 를 찾고 각자의 설정에 넣는 일은 [`../tools/mcp-register.mjs`](../tools/mcp-register.mjs)
가 한다.** 설치기는 그것을 부를 뿐 다시 구현하지 않는다. 그 위에 설치기가 얹는 것은 둘이다.

- **Claude Code 의 전역 등록.** `mcp-register` 는 Claude Code 에 아무것도 등록하지
  않는다 — 저장소의 `.mcp.json` 이 알아서 발견되는 것에 기대기 때문이다. 전역 설치에는
  그 파일이 없으므로 설치기가 user 범위로 직접 넣는다
- **CLI 마다 한 줄씩 찍는 최종 보고.** `mcp-register` 의 안내는 `if (!any)` 라서
  **셋 중 하나라도 찾으면** 아무 말이 없다. Claude Code 만 깔린 PC 에서 Codex 로
  일하는 사람은 `OK claude` 만 보고 자기 도구는 안 붙은 채 넘어간다

### 손으로 넣을 때

```json
{
  "mcpServers": {
    "axmap": {
      "command": "node",
      "args": ["<홈>/.axmap/app/mcp/server.mjs"],
      "env": {
        "AXMAP_AGENT": "홍길동",
        "AXMAP_ACTOR": "agent",
        "AXMAP_TTL": "45m"
      }
    }
  }
}
```

| 환경변수 | 뜻 |
|---|---|
| `AXMAP_REPO` | 대상 저장소를 **한 곳으로 고정**한다. 전역 설치에서는 **비운다** (아래) |
| `AXMAP_AGENT` | 이 에이전트의 이름. 여럿 붙을 때 서로 달라야 한다 |
| `AXMAP_SESSION` | 이 세션의 id. **안 적어도 된다** — 아래 |
| `AXMAP_ACTOR` | `agent`(대화형) / `background`(백그라운드) / `human` / `team` — 화면 색이 갈린다 |
| `AXMAP_TTL` | 기본 선점 시간 (기본 45m) |

### `AXMAP_SESSION` 은 서버가 알아서 정한다 — 이름이 겹쳤을 때의 마지막 그물

이름은 "누구인가" 이고 세션은 "어느 작업 주체인가" 다. 한 사람이 세션을 둘 띄우면
이름이 같아도 서로 다른 주체다. 장부가 이름당 레코드 하나였을 때는 **뒤에 온 쪽이
앞의 것을 덮었다** — 2026-08-28 에 두 번 재현됐다. 지금은 레코드가 (이름, 세션)
짝마다 하나라 덮지 않고, `ax_release` 도 **그 세션이 잡은 것만** 푼다.

서버는 `AXMAP_SESSION` → `CLAUDE_CODE_SESSION_ID` → `mcp-<pid>` 순으로 정해
CLI 를 부를 때마다 넘긴다. 앞 두 칸은 CLI 와 순서가 같아서, MCP 로 잡은 것을 셸에서
반납해도 같은 세션으로 인식된다. 마지막 칸은 **이 서버 프로세스 하나가 곧 한 세션**
이라는 뜻이라, 도구를 두 개 띄우면 자동으로 갈린다.

그러면 같은 이름의 다른 세션이 claim·release 를 시도할 때 **거부되고**(종료 코드 2)
앞 세션의 레코드는 그대로 남는다. 이건 그물이지 해법이 아니다 — **해법은 아래처럼
사람마다·세션마다 `AXMAP_AGENT` 를 다르게 주는 것**이다.

### 🔴 `AXMAP_REPO` 는 비운다 — 대상은 부를 때마다 다시 정해진다

서버는 도구를 부를 때마다 대상 저장소를 다시 정한다. 순서는 `AXMAP_REPO` → 도구의 절대 경로 `cwd` → 클라이언트 작업 폴더(roots) → 시작 폴더의 Git 루트다. 근거는 [DECISIONS.md의 D22](../docs/DECISIONS.md).

장부가 없는 repo도 첫 조회·선점 때 자동으로 준비한다. 기존 원격 장부가 있으면 이어 사용하고, 원격 접근 실패는 빈 장부로 바꾸지 않는다. roots가 여러 repo를 가리켜 대상을 고를 수 없으면 도구의 `cwd`를 지정한다. roots 미지원 클라이언트에서 실행 중 폴더를 바꿀 때도 `cwd`를 전달한다. 서로 다른 MCP 세션의 타겟은 독립적이다.

전역 등록인데 `AXMAP_REPO` 에 한 폴더를 박아 두면 **등록은 전역인데 대상은 한 곳으로
굳는다.** 다른 저장소를 열어도 아무 오류 없이 엉뚱한 장부에 claim 이 쌓인다.
그래서 설치기도 `mcp-register` 도 이 값을 **일부러 안 적는다.**

### 🔴 `AXMAP_AGENT` 는 반대로 반드시 적는다 — 다만 개인 설정에만

**저장소에 커밋되는 `.mcp.json` 에는 `AXMAP_AGENT` 를 적지 않는다.**
적는 순간 그 값이 clone 한 모두의 이름이 된다.

예전 이 저장소의 `.mcp.json` 은 이름이 없으면 모두에게 `claude` 를 줬다. 팀원 다섯이
clone 하면 장부에는 `claude` 라는 **한 명**만 존재하고, 겹침 판정은 자기 claim 을
겹침으로 보지 않으므로 다섯이 서로의 영역을 아무 경고 없이 덮어쓴다.
락이 조용히 다섯 명에게 발급된 것이고, 이 프로젝트가 fail-closed 로 막겠다고 한
바로 그 실패다. 그래서 그 줄을 지웠고 **기본 이름도 없앴다.**

전역 설치는 사정이 다르다. 쓰는 곳이 **홈 디렉터리 아래의 개인 설정**이라 커밋되지
않고, 팀 저장소가 아닌 폴더에서도 서버가 뜨는데 그런 폴더에는 `git config user.name`
이 없을 수 있다. 그러면 서버는 이름을 정하지 못하고 그냥 죽는다. 그래서 설치기가
**사람마다 다른 값**을 한 번 박아 둔다. 후보 순서는 이렇다.

1. `-Name` / `--name` 으로 준 값
2. `git config user.name`
3. OS 사용자 이름
4. 호스트 이름

**기본 전역 setup의 이름은 전역 Git 설정에서 정한다.** setup을 실행한 repo의 로컬 이름을 다른 repo에 가져가지 않는다. 명시적 프로젝트 설정에서는 해당 repo의 이름을 사용할 수 있다. 선점부터 반납까지 같은 이름·세션을 사용해야 한다.

이름 검증은 설치기가 다시 짜지 않고 저장소의 `agentNameError()` 를 그대로 부른다.
설치기가 통과시킨 이름을 서버가 거부하는 일이 없어야 하기 때문이다.
규격은 [SPEC.md](../docs/SPEC.md) 의 "에이전트 이름을 정하는 순서" 절에 있다.

### 남의 저장소에 붙일 때 — 프로그램은 여기, 데이터는 거기

전역 설치는 이 구분이 **정상 사용**이다. 무엇을 어디에서 잡느냐가 이 서버에서 가장
자주 틀리는 곳이고, 실제로 세 군데가 동시에 틀려 있었다.

| | 어디 | 왜 |
|---|---|---|
| `bin/axmap.mjs`, `tools/bus.mjs` | **`~/.axmap/app` (axMap 쪽)** | 실행할 프로그램이다. 대상 저장소에는 없다 |
| 장부 `.axmap/`, 쪽지함 `docs/bus/` | **대상 저장소 쪽** | 그 팀의 데이터다. 그 팀 저장소에 남아야 한다 |
| `ax_brief` 가 읽는 문서 | **대상 저장소 쪽** | 대상을 설명해야 한다 |

`ax_brief` 는 대상 저장소의 `CLAUDE.md`·`README.md`·`docs/` 만 읽고, 없으면
**없다고 말한다.** axMap 자신의 문서로 대신 채우지 않는다 — 낡은 지도는 없는 지도보다
나쁘고, 남의 지도를 자기 지도인 양 주는 것은 그보다 한 단계 더 나쁘다.

이 조합(`AXMAP_REPO ≠ axMap`)은 `test/mcp.test.mjs` 가 고정한다.
**자기 자신을 겨눠 놓고 시험하면 이 경로는 한 번도 안 돈다.**

### 설계

판정 로직을 여기서 다시 구현하지 않고 **`bin/axmap.mjs` 를 그대로 호출한다.**
두 경로가 갈라지면 장부를 믿을 수 없게 되기 때문이다.
관문 1(push CAS — **"내가 읽은 뒤로 바뀐 게 없을 때만 쓴다"**. git push 가 원래
이렇게 동작한다)과 관문 2(겹침 판정)가 CLI 와 완전히 동일하게 적용된다.

전송은 stdio + 줄바꿈 구분 JSON-RPC 2.0이다. MCP 서버는 SDK 없이 구현했다. 설치기는 `bin`, `src`, `mcp`, `tools`, `package.json`, `LICENSE`와 터미널 연결 의존성을 준비한다.

## 안 되는 것 / 아직 확인 못 한 것

**Codex CLI 등록은 임시 사용자 환경에서 실제 실행으로 확인했다.** `codex mcp list --json`으로 서버 경로·환경·시작 cwd를 확인하고 `codex mcp add`로 갱신한 뒤 다시 검증한다. TOML을 직접 파싱하거나 덮어쓰지 않는다. 모델 클라이언트별 roots 지원 여부는 별도 확인이 필요하다.

**개인 환경값은 보존한다.** Codex의 기존 `AXMAP_AGENT` 등 개인 환경값은 유지하며, 전역 setup은 예전 서버 경로·고정 `AXMAP_REPO`·시작 cwd를 제거한다. 이름을 따로 지정하지 않았으면 MCP가 작업 repo의 Git 설정에서 정한다.

**MCP `roots`는 1.3.0부터 지원한다.** 클라이언트가 지원을 선언하면 `roots/list`로 작업 폴더를 받고 변경 알림도 처리한다. 지원하지 않는 클라이언트는 시작 repo를 사용하고, 실행 중 경로 변경은 도구의 `cwd`로 전달한다. 프로토콜 회귀 테스트로 검증했으며 클라이언트별 실제 지원 여부는 별도 확인이 필요하다.

**같은 이름이 두 곳에 생길 수 있다.** 이 저장소 안에서 Claude Code 를 켜면 저장소의
`.mcp.json` 과 전역 등록이 둘 다 `axmap` 이라는 이름을 갖는다. 충돌로 깨지지는 않지만
**켠 위치에 따라 다른 정의가 뜬다** — 하나는 저장소 안의 `axmap/mcp/server.mjs` 를,
하나는 `~/.axmap/app/mcp/server.mjs` 를 가리킨다. 둘 다 도는 코드라 결과는 같지만
같은 코드는 아니다.

**팀 저장소의 `setup.ps1`/`setup.sh` 를 다시 돌리면 `agy` 등록이 되돌아간다.**
그 스크립트도 `mcp-register` 를 부르는데, 그쪽은 서버 경로를 그 저장소 안의 것으로
적고 이름을 지운다. 이 설치기를 다시 돌리면 원래대로 돌아온다.

**`doctor` 는 전역 등록을 검사하지 않는다.** 저장소의 `.mcp.json` 만 본다. 그래서
전역으로 설치한 PC 에서 `MCP 설정` 줄이 `~~` 로 뜨는 것은 정상이다 — 무게가 전역
등록으로 옮겨간 지금 그 줄은 거짓 보고에 가깝다. 설치 후에는 실제 전역 등록 경로도 함께 확인한다.
